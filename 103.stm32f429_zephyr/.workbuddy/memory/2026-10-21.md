## 103.stm32f429_zephyr 新建：Zephyr HTTP 服务器（F429IGT6 + LAN8720A）

**目标**：参考 009（Zephyr 工程骨架）与 101（同板裸机 LwIP 网络），在 Zephyr 3.7 上跑
HTTP 服务器；PB1 心跳、PB0 + 蜂鸣器网页控制。仅要求编译通过（硬件未连）。

**结果**：干净全量构建 0 警告。FLASH 89584 B / 1 MB (8.54%)，RAM 64232 B / 192 KB (32.67%)。

### 关键决策

- 用**项目内自定义 board** `boards/stm32f429ig/`（`-DBOARD_ROOT=<项目根>`），
  不复用 `nucleo_f429zi`：本板 176 脚 / 1 MB Flash / 25 MHz 晶振（nucleo 是 144 脚 / 2 MB / 8 MHz MCO）。
- 手写 BSD socket HTTP 服务器，不用 `CONFIG_HTTP_SERVER`（3.7 资源宏 API 刚重构，风险高；
  自写便于控制路由与内存）。
- 网络用 Zephyr **原生栈**（仓库无 lwip 模块）。

### 踩坑（重要，可复用）

1. **009 的 zephyr 树是按 H7 裁剪过的**：`dts/arm/st` 只有 h7、`hal_stm32/dts` 只有 h7、
   `stm32cube` 只有 stm32h7xx、`soc` 倒是全的。F429 项目不能直接复用，需补：
   - Zephyr v3.7.0 官方 tag 源码（补 `dts/`）
   - `hal_stm32` v3.7-branch 的 `stm32cube/stm32f4xx` + `dts/st/f4`（pinctrl dtsi 在 hal_stm32 里，不在 zephyr 仓）
   - 103 原始拷贝更残：只有 arch/boards/cmake/drivers。
2. **`CONFIG_NET_CONFIG_SETTINGS` 是门槛**：它 `default n`，不显式 `=y` 时
   `NET_CONFIG_AUTO_INIT` / `MY_IPV4_ADDR` 等全部不存在，表现为 `CONFIG_NET_CONFIG_MY_IPV4_ADDR undeclared`，
   连带 LOG_INF 的 cbprintf 宏报一堆 `_v1/_v2 undeclared` 假错误。
3. **必须开硬件 RNG**（`&rng status="okay"`）：否则 TCP 链接期
   `undefined reference to z_impl_sys_rand_get`。
4. **F4 在 Zephyr 里没有 over-drive**（`clock_stm32f2_f4_f7.c` 只在 F7 分支实现），
   所以按 168 MHz 配（M=25 N=336 P=2 Q=7），不用 101 的 180 MHz。
5. **LAN8720 复位（PCF8574 P7）必须钉在 I2C(prio 50) 与 ETH(prio 60) 之间**，
   用 `SYS_INIT(POST_KERNEL, 55)`；`st,stm32-ethernet` 绑定没有 `reset-gpios`，
   且驱动不处理。复位晚于 PHY ID 探测 = 网口静默不工作。
6. **PCF8574 无寄存器**，一次写替换全部 8 脚，必须维护影子字节，否则翻 P0 会误改 P7。
7. minimal libc **没有 sscanf**，请求行自己 split。
8. binutils 2.45 的 `LOAD segment with RWX permissions` 警告：`add_link_options` 与
   `CMAKE_EXE_LINKER_FLAGS` 都对 zephyr_final 无效，必须
   `target_link_options(zephyr_pre0/zephyr_final PRIVATE -Wl,--no-warn-rwx-segments)`（find_package 后 target 已存在）。
9. 构建需 Python 具备 pykwalify/PyYAML/pyelftools；managed python 没有，系统
   `D:\Software\Python3\python.exe` 有。CMakeLists 支持 `PYTHON3_EXECUTABLE` 环境变量覆盖。

## 追加：接入外部 SDRAM（用户要求"可以用 SDRAM"）

**做法**：控制器交给 Zephyr FMC 驱动（`&fmc` + `&sdram` + `bank@0`），
`app/sdram.c` 负责自检 + 8 MB `k_heap`，HTTP 线程栈优先从 SDRAM 分配，网页显示 SDRAM 可用量。

**结果**：干净全量构建 0 警告，FLASH 92312 B (8.80%)，RAM 64232 B (32.67%)，
链接输出出现 `SDRAM1: 0 B / 32 MB`（区域已登记，运行时分堆）。

### 新增坑（重要）

10. **Cortex-M4 默认把 0xA0000000–0xDFFFFFFF 当 Device memory**，SDRAM 的 0xC0000000
    正好在里；Device 属性下非对齐访问直接 BusFault、不可缓存。必须在 memory-region 节点上
    写 `zephyr,memory-attr = <DT_MEM_ARM_MPU_RAM_NOCACHE>`（`arch/arm/core/mpu/arm_mpu.c` 会建 region）。
11. **Zephyr F4 pinctrl 里没有 `fmc_ba0/ba1`**：BA0/BA1 复用 FMC_A14/A15，
    宏名是 `fmc_a14_pg4` / `fmc_a15_pg5`（pinmux 同为 PG4/PG5 AF12）。
12. **堆运行统计的结构是 `struct sys_memory_stats`**（`zephyr/sys/mem_stats.h`），
    不是 `sys_heap_runtime_stats`；需要 `CONFIG_SYS_HEAP_RUNTIME_STATS=y`。
13. **FMC 时钟 168/2 = 84 MHz**（不是 101 的 90 MHz），所以刷新计数按
    64ms/8192/11.9ns-20 = **636**（101 是 683）；时序沿用 101 的 2/8/6/6/2/2/2 —— 更慢的 SDCLK 下更宽松。
14. `k_thread_stack` 需 32 字节对齐（MPU），`k_heap` 只保证 8 字节 → 多申请 32 B 手工对齐。
