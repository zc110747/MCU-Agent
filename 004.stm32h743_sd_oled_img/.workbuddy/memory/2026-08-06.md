# 2026-08-06

## 完成：STM32H743 SD 卡 JPEG 轮播工程（从零搭建，Debug/Release 均零警告通过）

**目标**：SD 卡 `image/` 目录 JPG → 裁剪缩放 → 240×240 ST7789 OLED，5 秒周期轮播。

### 最终结构
```
Core/{Inc,Src,Startup}  Drivers/{CMSIS,STM32H7xx_HAL_Driver}
third_party/{fatfs(R0.16),tjpgd(R0.03)}  bsp/  app/  cmake/  tools/  .vscode/
CMakeLists.txt  CMakePresets.json  STM32H743ZITX_FLASH.ld
```

### 关键技术决策
- **裸机 while 循环**（不用 FreeRTOS），`app_slideshow_poll()` 靠 `HAL_GetTick()` 非阻塞计时
- **图像流水线**：`jd_prepare` 取原图尺寸 → 选最大的 1/1,1/2,1/4,1/8 硬解降采样（保证降采样后短边 ≥240）→ 中心裁剪成正方形 → 逐 MCU 块**反向映射 gather** 重采样进帧缓冲
  - 反向映射公式：`s = floor(d*side/FB)`，反解 `d0 = ceil(l*FB/side)`、`d1 = ceil((r+1)*FB/side)-1`
  - 已用 Python 仿真 10 组尺寸验证：240×240 每像素恰好写入 1 次，**零空洞零重复**
- **无 DMA**：SDMMC/SPI 全走 CPU polling，故 I/D-Cache 可全开，MPU 只留背景映射，缓冲区无需 32 字节对齐
- **RAM 布局**：RAM_D1(AXI 512K) 作主 RAM（帧缓冲 112.5K + TJpgDec 工作区 ~14K），DTCM/RAM_D2/RAM_D3/ITCM 全空闲且链接脚本已预留 `.dtcm/.ram_d2/.ram_d3` 段
- 占用：FLASH 59KB/2MB，RAM_D1 159KB/512KB

### 踩过的坑（重要）
1. **厂商驱动是 GBK 编码 + 制表符缩进** —— Edit 工具匹配失败，必须用 python 按字节 `open(p,'rb')` 替换，或先 `Read` 再改
2. **tjpgd 不能从 elm-chan.org 直接 curl**（返回 HTML）→ 用 GitHub raw `Bodmer/TJpg_Decoder`（是 ChaN 原版干净代码）
3. **`TJPGD_WORKSPACE_SIZE` 未含 JD_SZBUF 增量** —— 官方 3100/3480/9644 是按 JD_SZBUF=512 算的，我们设 4096 必须补 `+JD_SZBUF+512`
4. **Bodmer 版 tjpgd.h 多了 `jd->swap` 字段**，`jd_prepare` 会保留它 → 调用前必须 `memset(&jdec,0,...)`，否则字节序随机翻转
5. **`-O2` 下厂商 SPI 驱动触发 strict-aliasing 警告**（16 位写 32 位 TXDR 打包 FIFO，是硬件要求的访问方式）→ 加 `-fno-strict-aliasing`，不要改厂商代码
6. `drv_oled_text.c` 里 `uint32_t bytes_read` 传给 `f_read` 第 4 参数类型不匹配 → 改 `UINT`
7. 字库路径要从 `"1:/SYSTEM/FONT/"` 改成 `"0:/..."`（FF_VOLUMES 改成 1 了）
8. `LCD_CHFonts` 默认 NULL，未调 `LCD_SetTextFont` 时显示中文会空指针 → 在 `LCD_DisplayText` 中文分支加 NULL 保护跳过

- `cmake --preset debug` + `cmake --build --preset debug`（Ninja，全相对路径）
- OpenOCD 用内置脚本 `interface/stlink.cfg` + `target/stm32h7x.cfg`，无绝对路径
