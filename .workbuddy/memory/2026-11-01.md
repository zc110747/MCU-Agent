### 行尾归一（本轮最有复用价值的教训）

仓库 `core.autocrlf=true` 但**没有 `.gitattributes`**，且全局 skills 目录行尾**混杂**
（历史文件 CRLF、新写文件 LF）——而 `sync_skills.sh` 靠 `diff -rq` 判漂移，
一旦某次 `git checkout` 把镜像转成 CRLF，就会报"全库漂移"，且换机 clone 后两端口径不同。

处理：
1. 加 `.gitattributes` → `* text=auto eol=lf`（二进制由 git 自动识别，不受影响）；
2. 把全局 124 个文本文件归一化为 LF（去除 15048 个 CR）；
3. `git add -A` 后 `git status` **0 变更** —— 证明索引里本来就是 LF，工作区转换后与之完全对齐，
   **内容零差异**（`git diff --ignore-cr-at-eol` 为空）。

结论：镜像类仓库必须显式声明 `eol`，不能依赖 `autocrlf` 的隐式行为。
