## ⚠️ 重要更正：`mdk_target.c` 对 MDK-ARM **绝不能删**（推翻了前一条决策）

用户明确指出：**`mdk_target.c` 移出 MDK-ARM 会导致 `BKPT` 错误。**

### 根因（为什么编译链接能过、运行才炸）
- `mdk_target.c` 提供 ARMCLANG 的**半主机抑制**：
  `__use_no_semihosting`（AC5 `#pragma import` / AC6 `__asm(".global ...")`）+ `__ARM_use_no_argv`
  + `FILE __stdout` + `_sys_exit` + `_ttywrch`。
- 没有它时，只要代码里出现 `printf`/`fprintf`/`scanf`/`fopen` 等**任何走 C 库 I/O 的调用**，
  ARMCLANG 就会链入半主机实现 → 运行到 `_sys_open`/`_sys_write` 执行 **`BKPT`** → 停机。
- **延迟暴露**：当前若无裸 `printf`（如 006 只有 `snprintf`），符号被 `--gc-sections` 丢弃，
  编译链接全过、`BKPT` 计数为 0 —— 所以极易误判为「可以删」。一旦后续加入 printf 即爆。
- **`bsp_log.c` 不能替代它**：bsp_log 是应用层日志通道（`PRINT_LOG` → 自建 TX 环）；
  `_write()` 重定向有 `#if defined(__GNUC__) && !defined(__ARMCC_VERSION)` 守卫，MDK 侧根本走不到。
  两者职责不同，**必须共存**。
