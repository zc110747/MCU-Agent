## 修复 build_oneclick.bat 的 `:!MISSING!` 字面量 bug

双击运行报错并出现 `:!MISSING!`：根因是工具检测分支用 `!MISSING!` 延迟展开打印缺失工具名，一旦该分支触发且延迟展开未生效即原样打印。

- 重写全部 14 个 `build_oneclick.bat`：移除 `setlocal enabledelayedexpansion` 与任何 `!VAR!`，改为 `for %%T` 循环逐个 `where %%T`，缺失时直接 `echo [ERROR] Required tool not found: %%T`，用 `set "TOOLMISS=0/1"` 标记、顶层 `%TOOLMISS%` 判定；结尾 `if %ERR%==0 (...) else (...)`。
- 修复 Python 生成陷阱：原本 `"for %%T in (%s)" % tools` 中 Python `%` 格式化把 `%%` 吞成单 `%`，导致 `for %T` 语法错误；改为字符串拼接 `"for %%T in (" + " ".join(tools) + ") do ("`（已用 `od -c` 确认第 19 行为双 `%%`）。
- 14/14 结构校验通过（无 `!MISSING!`/`!ERR!`、for 循环 `%%T` 正确、括号平衡、英文、ST 含 Drivers/third_party 检查、出口 pause/exit 完整）。
- 技能 `stm32-project-scaffold` 新增第十节「一键编译 bat 规范（修正版）」，记录正确模板 + 两个坑（勿用 `!MISSING!`、Python 生成时 `%%`→`%`），用户级与工程级两份副本同步。

## 在 cmd / PowerShell 实测 build_oneclick.bat 并修复 `& ( )` 解析 bug

用户要求：在 cmd 和 powershell 上都测试，先验证 `001` 通过后再改其它。实测环境与结论：

- **沙箱限制**：Bash/PowerShell 工具均禁止启动 `cmd.exe`（"Invoking cmd.exe ... bypasses command validation"，即便关沙箱也拦）。唯一可运行 `.bat` 的方式是 PowerShell 工具原生 `& ".\xxx.bat"`（bat 本就由 cmd.exe 解释执行，故等效 cmd 上下文）。直接 `cmd.exe /c` 始终被策略拦截。
- **真实 bug（双击报错根因）**：实测 `001` 的 bat（上一版仅修了 `!MISSING!`）仍报 `此时不应有 into。`——来自目录检查 `echo` 行里**行首的 `(`**：`echo (or copy ..\support_tools\...\Drivers) into this folder` 被 cmd 当成命令组，遇 `)` 提前结束，余下 `into this folder` 成非法命令。后续又发现 `009` 的 `echo [STEP] Configure & Build ...` 里 **`&`** 被当命令分隔符，报 `'Build' 不是内部或外部命令`。
- **修复**：在生成器对所有 `echo`/`REM` 行做清洗——`&`→`and`、`( ) | < >`→删除（仅清洗这两类行，`if/for/cmake` 命令行的括号保留）。反斜杠 `\`（路径）在 cmd echo 中是字面量不受影响。
- **验证结果（全部在 cmd 解释器下）**：
  - `001`（STM32 CMake 预设）：clean build，日志无 `此时不应有`、含 `[DONE] Build succeeded.`、ELF 重建、exit 0。✅
  - `009`（Zephyr/west）：完整 `west build` 成功，`[DONE] Build succeeded.`，无 `当时不应有`/无 `'Build' 不是内部`。✅
  - `201`（ESP32-Arduino）：`arduino-cli` 存在→下载索引并尝试编译→仅因本机未装 `esp32:esp32` 平台失败（环境，非脚本），脚本正确捕获打印 `[ERROR] Build arduino-cli compile failed.`，无解析错误。✅
  - `202`（ESP32-IDF）：`idf.py` 缺失→工具检查正确打印 `[ERROR] Required tool not found: idf.py` 并 pause。✅
- 14 个 `build_oneclick.bat` 已全部用同一模板重生成；Python 确定性扫描确认所有 `echo/REM` 行不含 `& ( ) | < >`（仅有 `\` 路径，无害）。
- 测试产物（`ps_test.log`/`cmd_test.log`/`probe.log`、临时 `.fix_bat2.py`）已清理。

## 工作空间级一键编译所有项目脚本 build_all.bat

在仓库根目录（所有工程的上一层）新增 `build_all.bat`，一键顺序编译全部 14 个工程：

- 遍历固定列表（`001~010`/`101`/`102`/`201`/`202`）逐个 `call "<proj>\build_oneclick.bat" < nul`：`< nul` 把子脚本末尾的 `pause` 喂 EOF 使其立即返回（不再阻塞），父脚本据此统一控制暂停时机。
- **出错才暂停**：任一工程 `exit /b` 非 0 → 打印 `[ERROR]`，`pause` 等待用户回车后继续后续工程；成功则直接继续（不打断）。缺 `build_oneclick.bat` 的工程标记为 `[SKIP]`。
- 末尾输出汇总 `Passed / Failed / Skipped` 计数，并 `pause` 等待回车退出（避免双击后窗口直接关闭丢失结果）。
- 控制流用 `:build` 子例程（避开 `for` 内 `goto` 会中断循环的 cmd 老坑）；计数器用 `enabledelayedexpansion` + `!VAR!`。
- 验证：① 用 3 个 dummy 子脚本（成功/失败/缺失）做控制流测试，确认 `< nul` 跳过子 pause、errorlevel 正确回传、失败暂停后继续、汇总计数正确；② 对真实 `001` 工程 `call ... < nul` 实测：`cmake` configure→clean→build 全过，产出 `h743_tinyusb_cdc.elf`(FLASH 65668B/2MB=3.13%)，`ERRLEV=0`，证明 `< nul` 不干扰 cmake/ninja 且退出码正确回传。
