## 009.stm32h743_zephyr 移除 build 后无法重新编译（已修复并验证）

现象：删除 `build/` 后重新编译报两类错：
1. `west build -t clean`（build 不存在）→ 触发一次无 BOARD 的伪 configure，`BOARD is not being defined`（被 build_oneclick 当 WARN 吞掉）。
2. `west build -b ...` 实际 configure 失败：`ZEPHYR_TOOLCHAIN_VARIANT not set, trying to locate Zephyr SDK` → `Could not find Zephyr-sdk`（致命）。
   根因：脚本从未设置 `ZEPHYR_TOOLCHAIN_VARIANT` / `GNUARMEMB_TOOLCHAIN_PATH`。board `-b` 其实已正确传入，非 board 问题。

修复（三文件）：
- `CMakeLists.txt`：在 `find_package(Zephyr)` 前新增工具链自动探测——未设 `ZEPHYR_TOOLCHAIN_VARIANT` 时默认 `gnuarmemb`；未设 `GNUARMEMB_TOOLCHAIN_PATH` 时用 `find_program(arm-none-eabi-gcc)` 从 PATH 反推工具链根（`get_filename_component`）。零硬编码机器路径，符合 scaffold 规则。
- `build_oneclick.bat`：`where arm-none-eabi-gcc` 反推 `GNUARMEMB_TOOLCHAIN_PATH`（不硬编码）；`clean` 步骤改为 `if exist build` 才执行，避免缺目录时的伪 configure 报错。
- `.vscode/tasks.json`：`build` 任务由 `python -m west build -d build`（缺 -b，删 build 后必失败）改为 `python -m west build -b nucleo_h743zi/stm32h743xx -d build -s .`（与 configure 一致，支持全新构建）；顶层 `options.env` 注入 `ZEPHYR_TOOLCHAIN_VARIANT=gnuarmemb`。

验证：删除 `build/` + 清空工具链 env（`ZEPHYR_TOOLCHAIN_VARIANT=[]` `GNUARMEMB=[]`）后 `python -m west build -b nucleo_h743zi/stm32h743xx -d build -s .` → `BUILD_EXIT=0`，日志 `-- Found toolchain: gnuarmemb (D:/Software/tools/arm-none-eabi)`。资源 FLASH 286516B/2MB(13.66%)、RAM 169168B/512KB(32.27%)，与基线一致。VSCode F5（preLaunchTask=build）随之可用。

PowerShell 复核（用户要求）：同样「删除 build + 清空工具链 env」场景下用 PowerShell 跑 `python -m west build -b nucleo_h743zi/stm32h743xx -d build -s .` → `BUILD_EXIT=0`、elf 4569316B、资源占比同上。**编译确实通过**。
- 用户看到「编译不通过」的成因：PowerShell 把 `west` 输出到 stderr 的内容包装成 `RemoteException`/`NativeCommandError`（红色报错外观），但实际 `BUILD_EXIT=0`、elf 正常生成——属 PowerShell stderr→error 的误报，非真失败。
- `build_oneclick.bat` 收尾 `pause` 在非交互/PowerShell 下会卡死或返回 255，已改为去掉阻塞 `pause`、`exit /b %ERR%` 直接返回真实错误码（更利于 PowerShell/CI 调用）。注意：本沙箱同时禁用 `cmd.exe`（Bash/PowerShell 均无法直跑 .bat），故 .bat 端到端仅能在用户本机验证；其内核命令即上述已验证通过的 `west build`。
- 临时验证日志（`.workbuddy/ps_build.log`/`bat_ps.log`/`bat2.log`）已清理。

## 009 build_oneclick.bat 运行报 `此时不应有 .`（已修复）

现象：用户在 PowerShell 直接 `.\build_oneclick.bat` → 打印 banner 后立刻 `此时不应有 .。`，无后续 STEP 输出（属 cmd.exe 解析脚本本身的语法错误，非编译错误）。

根因（两处 cmd 解析雷区，均在我之前写的 .bat 内）：
1. `cd /d "%~dp0"` —— `%~dp0` 永远带尾随 `\`，变成 `cd /d "D:\...\009.stm32h743_zephyr\"`；行尾 `\"` 被 cmd 当转义引号 → 引号未闭合 → 后续 echo 行被吞 → 遇路径里 `.` 报 `此时不应有 .`。
2. `for %%T in (...) do ( where %%T >nul 2>&1 ... )` —— 括号块内 `2>&1` 的 `&` 被当成命令分隔符解析报错。

修复 `009/build_oneclick.bat`（整文件重写，干净 ASCII/CRLF）：
- `cd` 改为 `set "SD=%~dp0" & if "%SD:~-1%"=="\" set "SD=%SD:~0,-1%" & cd /d "%SD%"`（先去尾随 `\`）。
- `where %%T >nul 2>&1` → `where %%T > nul 2>nul`（消除 `&`）。
- 去掉阻塞 `pause`，`exit /b %ERR%` 直接返回真实错误码（兼容 PowerShell/CI）。
- 已 `file`/`grep` 验证：无 `2>&1`、无 `cd /d "%~dp0"`、无 `&` 字符，DOS batch ASCII CRLF。

同步修复 `stm32-project-scaffold` SKILL.md（避免新工程复现）：
- 致命坑 1 示例 `where %%T >nul 2>&1` → `> nul 2>nul`。
- 第十一节 `cd /d "%~dp0"` 推荐写法补充「必须先去尾随 `\`」。
- 新增「致命坑 4」：专门记录 `cd /d "%~dp0"` 尾随反斜杠 + `for` 块内 `2>&1` 触发 `此时不应有 .` 的机理与正确写法。

注：本沙箱禁用 `cmd.exe`，`.bat` 端到端无法在此复跑，需用户在本机 PowerShell 重新 `.\build_oneclick.bat` 验证。
