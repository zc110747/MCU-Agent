## flash-esp32.bat 双击“无反应”修复
- 现象：build_oneclick.bat 双击正常，flash-esp32.bat 双击“无反应”。
- 根因（非脚本崩溃）：旧脚本无 COM 参数时进入 `set /p "Select port number"` 等手输编号，且上传日志 `> flash-esp32.log 2>&1` 吞屏，窗口看似“卡住/没反应”。编码与 build 一致（均 LF 无 BOM），依赖齐全（arduino-cli/python/pyserial 均在 PATH）。
- 修复：重写 flash-esp32.bat 为**双击自动识别 ESP32 端口一键烧录**——pyserial 扫 `lp.comports()`，按 `hwid` 含 `303A`（Espressif USB VID，ESP32-S3 内置 USB=VID:PID=303A:1001）自动选口；上传改为 `> log` 再 `type log` 回显；所有出口均明确提示并 pause。
- 验证：本机当前串口 COM1(物理)/COM8(FTDI 0403:6001)/COM22(ESP32-S3 303A:1001)，自动识别命中 COM22。
- 用法：双击=自动烧 COM22；`flash-esp32.bat COM22`；`flash-esp32.bat COM22 monitor`；`--no-pause` 用于 CI。板子未插时提示插板并 pause（不再是“无反应”）。
- 经验已回写 skill `esp32-arduino-cli-build`：flash 脚本必须自动识别 ESP32 VID 303A，否则双击会停在选端口被误判为无反应。

## GPIO48 WS2812B 状态灯控制（用户需求）
- 需求：开发板 GPIO48 上有 WS2812B（板载 RUN LED，单线 GRB 800kHz），在 **GPIO 界面**提供控制：R/G/B 单个闪烁、RGB 循环闪烁、关闭。
- 实现：`debug/ws2812_led.{h,cpp}` 用 `Adafruit_NeoPixel`(1px, GPIO48, NEO_GRB+NEO_KHZ800, 亮度40) + FreeRTOS 任务做状态机（OFF/BLINK_R/BLINK_G/BLINK_B/CYCLE_RGB，250ms 半周期）。`ws2812_set` 命令(`mode`=off|r|g|b|cycle)经 WebSocket/REST 下发；模式变化推 `LED_STATE` 事件(`type:"led"`,`mode` 0..4)回显网页同步。
- 关键：GPIO48 从 `pin_config.h` 的 RESERVED_PINS(原 {19,20,48}) 移出，改由 LED 控制器 `PinManager::claim(48,"LED")` 独占；`gpio_monitor` 仍只管 4/5/6/7。`build_oneclick.bat` 增加安装 `Adafruit NeoPixel`；`.ino` 增加 `#include "debug/ws2812_led.cpp"`。
- 编译结果：Flash 1,030,531 B(78%) / DRAM 80,700 B(24%)，0 error 0 warning（Adafruit_NeoPixel 1.15.5）。
- 踩坑（环境特性）：同一条消息里对**同一文件的多处 Edit 偶尔静默不生效**（web_pages.h 的 updateLed/fetch 块、debug_gateway.h 的 `led()` 访问器、debug_gateway.cpp 的 include 均首次"成功"但未落盘）。**对策：每次批量 Edit 后必须 Read 复核，失败时显式重做**。本次因此多耗一轮编译才定位。
- 文档：`user_document.md` 5.3 新增 WS2812 控制说明 + §6.1/§7 增 `ws2812_set`/`led` 事件；README 特性表增 WS2812 行、约束改写。
