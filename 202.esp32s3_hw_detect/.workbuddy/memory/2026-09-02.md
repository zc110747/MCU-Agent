## flash-esp32.bat 双击“无反应”修复
- 现象：build_oneclick.bat 双击正常，flash-esp32.bat 双击“无反应”。
- 根因（非脚本崩溃）：旧脚本无 COM 参数时进入 `set /p "Select port number"` 等手输编号，且上传日志 `> flash-esp32.log 2>&1` 吞屏，窗口看似“卡住/没反应”。编码与 build 一致（均 LF 无 BOM），依赖齐全（arduino-cli/python/pyserial 均在 PATH）。
- 修复：重写 flash-esp32.bat 为**双击自动识别 ESP32 端口一键烧录**——pyserial 扫 `lp.comports()`，按 `hwid` 含 `303A`（Espressif USB VID，ESP32-S3 内置 USB=VID:PID=303A:1001）自动选口；上传改为 `> log` 再 `type log` 回显；所有出口均明确提示并 pause。
- 验证：本机当前串口 COM1(物理)/COM8(FTDI 0403:6001)/COM22(ESP32-S3 303A:1001)，自动识别命中 COM22。
- 用法：双击=自动烧 COM22；`flash-esp32.bat COM22`；`flash-esp32.bat COM22 monitor`；`--no-pause` 用于 CI。板子未插时提示插板并 pause（不再是“无反应”）。
- 经验已回写 skill `esp32-arduino-cli-build`：flash 脚本必须自动识别 ESP32 VID 303A，否则双击会停在选端口被误判为无反应。

## WebSocket 服务端主动推送 state 快照（界面实时化，四项需求一次性解决）
- 需求：①GPIO set/clear 后按**实际**电平更新 HIGH/LOW；②WS2812 取消彩色高亮、改为显示**实际工作状态**；③PWM apply 后实时显示状态；④ADC 实时更新。手段限定 WebSocket 服务端推送。
- 根因归纳：四项需求是同一个病——界面显示"命令回显"而非"硬件状态"。故不给控件打补丁，改做统一状态通道。
- 实现：`AppConfig::STATE_PUSH_INTERVAL_MS=400`；ws_task 每 400 ms 且**仅当 `_clients>0`** 时 `broadcastState()`（`{"type":"state", gpio[], led{}, pwm{}, adc[], adc_src}`）；`onConnect()` 里 `_lastState=0` 使新页面立即收首帧；无客户端零开销。
- **关键架构决策：state 快照不进 EventBus**。做成 DebugEvent 会让其 sizeof 从 ~220B 膨胀到 800B+，深度 64 的队列多占约 37KB DRAM；改为 ws_task 内直接读模块缓存 + `broadcastTXT()`，DRAM 仅增 276B。**经验：周期性大帧状态广播要绕开事件队列，事件队列只承载"变化"。**
- `adc_monitor` 增 `latest(raw[],volts[])` 缓存供快照读取（不额外占 I2C）；`ws2812_led` 除 mode 外维护实时输出 `_on/_r/_g/_b`；`pwm_output` 发布 LEDC 量化后的**实际** freq/resolution。
- 前端 `web_pages.h` 全量重写：Interface 拆 4 卡片；删全部 `setInterval` 轮询与断线 `location.reload()`（改 3s 自动重连）；WS2812 选中态仅中性描边（删原 `background:'#2a7'` 绿高亮）并显示 `模式 | ON rgb(r,g,b)`；PWM 回填输入框但**聚焦中不覆盖**；ADC 曲线峰值自适应缩放。

## 提交前抓到 sed 的 CRLF 破坏（差点提交 1762 行假 diff）
- 现象：`git diff --numstat` 显示 `prompter.md` 1762 删 + 1762 增（实际只改 1 行目录树）。
- 根因：**Git Bash 的 `sed -i` 会剥掉 CRLF**。该文件当初 autocrlf 未生效、以 **CRLF 存进 blob**（旧 22047B/1762 CRLF），
  sed 重写后变纯 LF（20283B/0 CRLF）→ 整份文件逐行不同。同批 sed 的其他文件（README/DELIVERY/user_document/.ino/.cpp）原本就是 LF，未受影响。
- 修法：`git checkout -- prompter.md` 恢复 → **Python 二进制模式**替换行内容（只换 `├── debug/` → `├── bsp/`，不碰行尾 `\r`）→ numstat 收敛为 1/1。
- **判据（提交前必查）**：`git diff --numstat`，若某文件**增删行数 ≈ 文件总行数**即中招。
- **教训**：批量 sed 前先抽查行尾——用 python 对比 `open(f,'rb').read().count(b'\r\n')` 与 `git show HEAD:f` 的计数；跨行尾批量改写一律用 Python 二进制模式，别用 sed。已写入用户级 MEMORY.md §五。
