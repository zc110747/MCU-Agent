## 修复 Keil MDK-ARM 编译报错 (2026-08-28 续)
- 现象：121 个 .c 编译通过，仅 `port.c`(FreeRTOS GCC 端口, 含内联汇编) 与 `startup_stm32f429xx.s`(汇编) 未生成 .o → 报错。
- 根因：生成的 uvprojx 中 `<Cpu>` 字符串格式错误：`IRAM(0x20000000-0x2002FFFF)…FPU4(SFPU)`（Keil 要求 `start,size` 逗号格式，且 FPU 用 `FPU2`），导致 Keil 未正确识别 Cortex-M4+FPU 目标，汇编/内联汇编路径失败（纯 C 不受影响）。
- 参考 `embedded_based_on_stm32/.../03-01-01_STM32F429_FreeRTOS` 的 uvprojx/uvoptx（其本身为双 Target：AC5=ARMCC V5 用 RVDS 端口 / V6=ARMCLANG 用 GCC 端口）对齐设置。
- 修改 gen_uvision.py 后重新生成：Cpu 改 `IRAM(0x20000000,0x00030000) IRAM2(0x10000000,0x00010000) IROM(0x08000000,0x00100000) …FPU2`；Cads 对齐 V6（Optim=2, wLevel=3, v6Rtti=1）；补 FlashDriverDll/UL2CM3、DriverSelection=4096、DllOption `-MPU`；增 HAL `Inc\Legacy` 包含路径；删除多余 `__VFP_FP__` 宏（FPU2 由工具链自动预定义）；uvoptx 闪存参数改 FL0100000(1MB)。
- 结论：FreeRTOS 仍用 GCC 端口（与参考 V6/ARMCLANG 一致，RVDS 端口仅适用于 ARMCC V5）；syscalls.c 未加入（MicroLIB 替代）。
- 待用户在 Keil 实测：若其实际用 ARMCC V5，则需切到 RVDS 端口（可加 V5 Target，参考已演示双 Target 结构）。
- 收尾对齐：DbgClock 由 5MHz 改 10MHz 与参考一致；重新生成后自动校验全过（XML 合法、123/123 文件存在、Cpu 逗号+FPU2、无 __VFP_FP__/syscalls/FPU4、uvoptx FL0200000=0、DbgClock=10000000、Protocol=2 SWD）。沙箱无法跑 Keil，需用户 Rebuild 实测确认。
