## 106.stm32h429_video：移植《实验47 视频播放器》+ code-style 施工

**运行形态**（用户选定）：FreeRTOS V11 + LVGL 8.3，8080 MCU 屏，HAL 时基 **TIM12**
（prio 0），SysTick 归内核；heap_5 **3 MB** 落 SDRAM `0xC0000000`，
`LV_MEM_ADR = 0xC0300000`（256 KB）。

**与例程的三处结构性改动**（后续维护要守住）：
1. libjpeg 不再直写 GRAM/DMA2D → `jdmerge.c` 改成 RGB565 **行钩子**
   （`mjpeg_row_buffer` / `mjpeg_row_emit` / `mjpeg_pool_alloc`），结果落 SDRAM surface，
   LVGL 用全屏 `LV_IMG_CF_TRUE_COLOR` image 合成。升级 libjpeg 必须重放这两处改动。
2. 音频四缓冲手工轮转 → SAI 双缓冲 + 二进制信号量；prefill 两半后 play + unmute。
3. 文件切换不用 `dir_sdi()` + `DIR.blk_ofs` → 启动时 `f_readdir()` 收集播放列表（≤32）。

**DMA2 Stream 分配是硬约束**：SAI 占 Stream3，SDIO 读占 **Stream6**。
105 的旧 `bsp_sdio.c` 用 Stream3，直接拷会抢流。

**构建**（无硬件，仅编译级验收，四份零警告）：
- GCC Debug FLASH 294768 / RAM 23712；Release FLASH 326456 / RAM 23744
- MDK Release Code 223896 RO 58808 RW 248 ZI 3167776；Debug Code 376006 ZI 3167744
- fromelf BKPT = 0（此前报的 5 处确认是反汇编误判，本次重建后为 0）

**code-style 施工要点**（照 `mcu-code-style` §10 + references/apply-to-legacy-project.md）：
- clang-format 只有 VSCode cpptools 自带那份 23.1.0 可用（`command -v` 查不到，走
  `~/.vscode/extensions/ms-vscode.cpptools-*/LLVM/bin/clang-format.exe`）。
- 数据表只做 `sed s/\t/    /g`，用 `git diff -w` 证空白；`lv_gbk_map.c` 是生成文件不动。
- `bsp/lcd_fonts.h` 是 **GBK** 文件 → `extern "C"` 用 python 按 gbk 编解码插入，保住原字节。
- static 合并后 `s_lcd_fs_info`（3332 B）等大对象仍在 .bss；RAM 由 23512 → 23712（+200 B，
  结构体对齐所致，非泄漏）。

**注释策略**：文件头从 10~44 行压到 2~4 行，坑/时序/取证全部下沉到
`document/stm32f429/video_player_port.md`（A1~A10），代码里 `@note` 指小节号。
比较省事且信息不丢的做法：脚本读原 `@file/@brief` 生成新头，再单独补 `@note` 表。

**顺带修掉的陈旧注释**（从 105 抄来的错）：`lv_port_disp` 写成 ST7789 240x240 /
`driver_spi_oled_init`（实际是 FMC NT35510 800x480）、`bsp_lcd_text` 把 `1:` 当 SD 而
本工程 `FS_VOL_SD = "0:"`、绘制缓冲写 57 kB（800 宽实为 96000 B）。
