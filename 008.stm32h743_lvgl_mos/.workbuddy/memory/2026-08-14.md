## 2026-08-14（续）— 相机在真机（#002 板）实测 + 修复

### 关键澄清
- **COM19(ST-Link VCP) 与 COM4(USB CDC) 是同一块带 OV5640 的相机板**（#002 项目在其上验证正常）。此前 `ov5640 init failed` 不是「无传感器」，而是 #008 端口缺陷。

### 与 #002 对齐的修复（#34，全部已落地）
1. **I2C4 时序**：`hi2c4.Init.Timing` 由 `0x20A09DEB`(#005 值) → `0xF0421E25U`(#002 验证值)。两项目 D3PCLK1 均 = 120MHz，故同一时序值产生相同 SCL。
2. **I2C4 上拉**：PF14/PF15 由 `GPIO_NOPULL` → `GPIO_PULLUP`（#002 用 PULLUP）。
3. **DCMI DMA**：`DMA2_Stream7`+`MemBurst SINGLE`+优先级0 → `DMA2_Stream1`+`MemBurst INC4`+`VERY_HIGH`（#002 验证配置）；同步更新 `stm32h7xx_it.c` 的 `DMA2_Stream1_IRQHandler`、`main.c` 的 `MX_DMA_Init`（Stream1 中断使能/优先级5）、`MspDeInit` 关 Stream1 IRQ。
4. **AF 固件下载改为非致命**（根因）：`dcmi_ov5640_download_firmware()`（OV5640 AF MCU blob）此前失败即 `return RT_FAIL` 导致整个 init 失败。该 blob 在 #002 板的 OV5640 模组上不被接受；但 AF 固件对 RGB565 流媒体非必需（#002 从不下载它）。改为失败仅打印 `[CAM ] warning: AF firmware download failed (non-fatal)` 并继续。

### 真机实测结果（最终 Release，0 错 0 警，Verified OK）
- `cam open` → `OV5640 detected (id=0x5640)` → `ov5640 camera init success!` → `camera ready: sensor 320x240, crop 96x96` → `live preview started`。
- `cam info`：**live 43fps, frames 递增, overruns 0**（三缓冲 + 32 对齐 + DMA 完成 invalidate 缓存，无割裂）。
- 3× 开/关循环：每轮 `d2` 回到 **294872/294912**，`sram check d2` 全 `integrity ok` → 共享池无泄漏/无损坏。
- **NES 后续回归**：`open nes`→`OK open 3 nes`(4 ROMs)，`d2 1992/294912`；`menu` 退出后 d2 回升、`integrity ok`。
- 全程控制台即时响应，无死机/冻结。

### 结论
两个用户注意点全部满足：① 摄像头缓冲与 NES 共享 `sram_pool`(RAM_D2)，进入申请/退出释放，三缓冲；② 整系统稳定、实时预览无割裂、退出后 NES 正常。已知限制：该 OV5640 模组 AF 固件加载失败（不影响 96×96 预览，固定/手动对焦模组无需 AF）。
