## 第二轮：布局加大 + COM9 死机修复（下午）

- 虚拟手柄区域加大：PadSize 52→58、Gap 8→14、新增 Spacer=36 拉开方向键与A/B两组间距；窗体 1100→1180、右列 70%→72%；kp 改为三列 [dpad|spacer|abStart] 并始终居中。
- COM9 连接一会死机根因与修复：
  1. **BeginInvoke 堆积**（主因）：DataReceived 高频触发每次 BeginInvoke 到 UI 线程，消息队列爆满→卡死。改为：DataReceived 只 ConcurrentQueue.Enqueue，UI 用 100ms 节流 Timer（RecvTimer_Tick）批量取 ≤4096 字节，更新频率恒定。
  2. **SerialPort.Close 死锁**：Close 可能等待接收线程→UI 卡死。改为 FormClosing 设 _closing、停 timer、移除事件、Task.Run 后台 Close。
  3. **扫描枚举竞争**：已打开时不再调用 GetPortNames（部分驱动下极慢/卡死），仅未打开时刷新。
  4. **SendLine 阻塞 UI**：改为 Task.Run 后台 Write。
  5. **背压+日志上限**：队列 >1MB 丢旧数据；日志文本上限 20KB→8KB。
- 联调限制：本环境无 COM9 下位机/可用串口，无法真机联调；已做 build 通过 + 启动冒烟（无崩溃）+ 算法级压测（队列有界可消费）。请用户在本地连 COM9 实测，如仍死机请反馈下位机是否持续高速发送及波特率，再迭代。
