# 2026-09-12 — 011.stm32h743_freertos_emwin

## 主题：emWin 信息面板"界面不显示 / 字反了"两个根因定位并修复

### 1) 界面上没有任何文字 —— 自定义字体回调没推进光标（已修）
- 现场：能编译、能烧录、能运行，帧缓冲里也确有像素，但**每行只有 1 个字符宽**，
  整串字符全叠在字符串起点的同一个 x 上。
- 根因：`GUI_ENC_APIList_EXT.pfDispLine = GUIPROP_EXT__DispLine` 只做
  「解码 → 调 `pfDispChar`」循环，**自己不移动光标**；`DispPosX += XMag*XDist`
  必须由字体回调自己做（emWin 内置 `GUIPROP_EXT_DispChar` 末尾就是这条 store）。
- 修法：`Bsp/emWin/emwin_font_gbk.c::emwin_gbk_disp_char()` 末尾补
  `GUI_GotoX(x0 + XMag*dist)`；同时把"未映射字符提前 return 导致漏推进"也修掉。

### 2) 字是反的 —— 编译期 ASCII 点阵是 LSB-first，代码按 MSB-first 读（已修）
- 现象：`/` 显示成 `\`，`F` 的竖笔在右边（整字左右镜像）。
- 判据：① 原始 blitter `Bsp/drv_spi_oled.c::oled_display_char()` 用
  `if (disChar & 0x01)` + `>>= 1` → bit0 即最左像素；
  ② `ASCII_1608_Table` 的 `(` 只有 LSB-first 才读成左括号（MSB-first 会变右括号）。
- 修法：`draw_lsb_rows()` 删掉 `msb_first` 参数，统一 `bit = 1u << (col & 7)`。
  汉字路径本来就是 LSB-first（`Convert_Font_MSB_Column_to_LSB_Row()` 输出
  `1 << (col%8)`），未受影响。

### 3) 顺带纠正的两个结论（写进 README 与 skill）
- 颜色转换必须用 **`GUICC_M565`**（`GUICC_565` 产出镜像 B5G6R5，红蓝互换）。
- emWin 的 565 转换是**四舍五入** `(v*31+127)/255`（绿用 63），不是 `v>>3`；
  之前用截断公式写校验脚本，误把 `0xB0`/`0xD0` 的 1 LSB 差当成固件 bug。

### 4) 只写面板的验收方法（已固化为 tools/）
- `tools/verify_framebuffer.py`：从当次 ELF 解析 `gui_vram` 符号 → OpenOCD
  `dump_image` → 逐像素断言（调色板/M565 舍入/标题居中/文字铺满行），给 pass/fail 计数。
- `tools/render_framebuffer.py`：把帧缓冲打成字符画，"肉眼"看屏幕（本次靠它一眼看出镜像）。
- **关键坑**：抓帧地址必须取自当次 ELF。用旧地址（0x24021260 vs 真 0x24021280）会
  整体偏移 +16 像素、首行混入相邻变量，看起来像"画面错位"的严重 bug。
