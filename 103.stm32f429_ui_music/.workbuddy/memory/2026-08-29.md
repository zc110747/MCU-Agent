## 本轮修复（第二波，用户上板实测后反馈）

用户连板、释放 COM7 后默认正常，但点屏上任意按钮（播放/上/下一首）整板死机；另有中文曲名乱码、内存占用担忧。三项处理：

1. **点击死机（致命，已修复）**：根因 = 共享解码上下文 `s_dec` 在 ui 任务（按钮回调）与 audio 任务间无互斥，播放中切歌清零 `s_dec` 而 audio 任务正 `audio_decoder_read` 用已清零字段 → NULL 解引用 → HardFault → 整板冻结。
   - 修复（`app/audio_player.c`）：`s_lock = xSemaphoreCreateRecursiveMutex()`；所有 API 包 `PLOCK_TAKE/PLOCK_GIVE`；`player_load` 拆持锁内部版 `player_load_locked` + 公开包装；`player_task` 先无锁等空半区信号量、拿锁后复核 `PLAYING&&opened` 才解码；`player_toggle` 嵌套靠递归互斥量。
   - 前提：`app/FreeRTOSConfig.h` 已开 `configUSE_RECURSIVE_MUTEXES=1`。
2. **内存占用（非问题）**：解码器本就增量流式（`read_mp3_frames`/`read_wav_frames` 每次只 `f_read` 小块，SAI 双缓冲仅 16 KB SDRAM），只持文件描述符+解码头；无需改结构。已写入 README §8.3。
3. **中文曲名乱码（已修复）**：`third_party/FatFs/ffconf.h` `FF_LFN_UNICODE` 0→2（长文件名返回 UTF-8），匹配 `lv_font_gbk` 的 Unicode 输入；`FF_CODE_PAGE` 仍 936。`audio_player.c` 扫描处 `snprintf` 用 `%.*s` 限长修 `-Wformat-truncation`。

## 点击死机真因更正（第三波，关键）
- **上面的「共享 s_dec 无互斥」根因判断错误**：递归互斥量 + SAI DMA IRQ 6→5 两次修复后仍死机，说明那不是死机根因（互斥量保留作双保险，确实消除了真实并发竞争，但非 freeze 因）。
- **真因 = minimp3 栈上 ~16 KB 局部变量溢出任务栈**：`mp3dec_decode_frame()` 在栈分配 `mp3dec_scratch_t`（含 `syn[33][64]`、`grbuf[2][576]` 等，约 16 KB）。该调用发生在 `ui_task`（首次点击，原栈 1536 words=6 KB）与 `player_task`半缓冲 refill（原栈 2048 words=8 KB）——均 <16 KB，**栈向下溢出踩坏 SDRAM FreeRTOS 堆**，随后野指针写入触发 imprecise 总线错 `CFSR=0x400`(IMPRECISERR)→HardFault→Error_Handler 死循环。WAV 路径仅 `static tmp[256]`，故“仅 MP3 死机”完全吻合。OpenOCD 抓 `PSP=0xc0005db8`（合法堆内）也排除“溢出到未映射 SDRAM”。
- **修复**：`UI_TASK_STACK_WORDS` 1536→6144(24 KB)；`player_task` 栈 2048→6144(24 KB)。同时恢复 `sai_audio_start()` 被 `#if 0` 的 `HAL_SAI_Transmit_DMA`，删除 `ui_task.c` 临时自动播放块。
- 双构建零警告（Debug FLASH 44.47%/RAM 31.95%；Release FLASH 49.72%）已重测通过。
- **真机点击验证待用户烧录确认**：本会话 ST-Link 卡 `LIBUSB_ERROR_ACCESS`（异常退出 OpenOCD 残留 WinUSB 句柄），`pnputil /restart-device` 或重插可解；验证步骤见 README §8.7（串口 USART3 115200 发 p/n/v，看 `[CMD]` 回显且不断电；可连 OpenOCD 读 `mdw 0xE000ED28`(CFSR) 应为 0）。

## 驱动审计 + 大缓冲迁 SDRAM（第四波，对照正点原子 实验45 参考）

用户给 10 个参考文件（HARDWARE/WM8978/wm8978.c·h、HARDWARE/SAI/sai.c·h、APP/audioplay.c·h、AUDIOCODEC/wav/wavplay.c·h、HARDWARE/IIC/myiic.c·h），要求“找出驱动里不正确的地方（不直接抄，提取有效信息更新），并让 MP3/WAV 大缓冲都用 SDRAM”。

### 1. WM8978 寄存器 bug（致命无声根因，已修 `bsp/bsp_wm8978.c`）
- **错**：原 `wm8978_init()` 把 I2S 格式写到 **R10（DAC Control）**=0x02，且 **R4（Audio Interface）** 留 0x00（右对齐 16-bit）→ CODEC 与 SAI（I2S 主发）线制不一致 → 静音/乱码。
- **对（参考 `WM8978_I2S_Cfg(2,0)` → R4=(2<<3)|(0<<5)=0x10）**：R4=0x10（飞利浦 I2S / 16-bit）。
- 按参考 `WM8978_Init()` 重写：`R1=0x1B,R2=0x1B0,R3=0x6F`(0x6C|DAC使能0x03),`R6=0,R43=0x10,R47=0x100(LDAC2LMIX),R48=0x100(RDAC2RMIX),R49=0x06(TSDEN+SPEAKERBOOST),R10=0x08(SOFTMUTE关+128x),R14=0x08`；并显式写 R50/R51=0x01(DAC-out 使能)、R11/R12=0xFF(DAC 数字音量)、R52/R53=0x3F(耳机模拟 0dB)。
- **音量 API 修正**：`wm8978_set_volume` 原写 R52/R53（耳机模拟，6 位）→ 改写 **R11/R12**（8 位 DAC 数字音量，0..100 线性映射到 0x00..0xFF），耳机模拟固定 0x3F。
- R49 原误用作 RDAC2RMIX（实为 TSDEN/SPEAKERBOOST 寄存器）已纠正。

### 2. 大缓冲迁 SDRAM（已修 `app/audio_decoder.c`·`h`）
- `dec_ctx_t.mp3_buf[4096]` → `uint8_t *mp3_buf`；`static int16_t s_pcm[2304]` → `static int16_t *s_pcm`；二者在 MP3 `audio_decoder_open` 经 `pvPortMalloc`（SDRAM 堆）分配，所有错误返回路径与 `audio_decoder_close` 均 `vPortFree`。
- 链接证实：`s_pcm` 在 `.bss` 由 0x1200(4608B) 降为 0x4（指针）；原 8704 B 大缓冲现运行时落在 SDRAM。
- SAI DMA 双缓冲（16 KB）本就在 SDRAM。WAV 解码无独立大缓冲（直接填 SAI 缓冲）。

### 3. SAI 时钟（保留，硬件标定项，不盲改）
- 参考用 PLLI2S + 每采样率 `SAI_PSC_TBL` 分频；本板按项目铁律走 PLLSAI（无 `Sai1ClockSelection`）固定 48 MHz + Mckdiv=3。音调/MCK 仍待示波器+听感确认（README §8.2）。
