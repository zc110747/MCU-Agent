## MDK-ARM 工程适配（同日追加）

以 013 的 MDK-ARM 目录为模板改造（013 目录是整套连 Objects/Listings/旧日志一起拷来的，已清空重来）。
两个 target 保留 debug(Optim=0) / release(Optim=5)，AC6.14，`stm32h743.sct` 自绘。

文件组：Application/Startup、Application/User、Bsp、Bsp/Camera、Mouse、Protocol、Usb、
Algorithms、Middlewares/TinyUSB、Drivers/STM32H7xx_HAL_Driver（17 个 HAL 模块，须与
CMakeLists 的 HAL_SOURCES 逐项一致）。

### 踩到的四个真问题（都是"能编过但不是你以为的那样"）

1. **`<Define>` 有两份：Cads 与 Aads。** 把 C 的 `CFG_TUSB_MCU=OPT_MCU_STM32H7` 一并写进
   汇编侧 → armasm 把 `A=B` 当 SETA 赋值，报 `A1516E: Bad symbol`。汇编侧只放裸符号
   （`STM32H743xx`）。
2. **HAL 组必须含 `stm32h7xx_hal.c`**（基础文件，非 `hal_xxx`）。漏了会在链接期报
   `HAL_Init / HAL_GetTick / HAL_IncTick / uwTickPrio` 未定义 —— 编译阶段完全看不出来。
3. **`_Static_assert(BTN_LEFT_PORT == BTN_RIGHT_PORT, ...)` 在 AC6 直接报错**：两个外设指针
   比较不是整型常量表达式（"cast that performs reinterpret_cast"）。GCC 会折叠所以没暴露。
   改成按表逐脚 `HAL_GPIO_Init`，顺带取消"左右键必须同端口"的限制。
4. **`__attribute__((section(".cam_buf")))` 在 armclang 下是 PROGBITS 而不是 NOBITS。**
   后果：armlink 把 75 KB 零存进 Flash（RW-data 77248B），启动时 scatter load 再拷回 D2，
   把"首传前无脏行"的不变量破坏掉。
   - `__attribute__((zero_init))` **无效**：armclang 直接报 unknown attribute（那是 armcc 的）。
   - 唯一可行写法：`#pragma clang section bss=".cam_buf"` + 数组自身 `aligned(32)`，
     实测段类型 NOBITS、对齐 32、零警告。已封装成 `bsp.h` 里的
     `BSP_DMA_BUF_BEGIN/ATTR/END` 三件套（GCC 侧展开为普通 section 属性）。
   - 修完 RW-data 77248 → 192 B，Load Region 162240 → 85088 B。

### 构建结果（UV4 -b，AC6.14 / MDK 5.31）

| target | Code | RO-data | RW-data | ZI-data | Flash 占用 | 告警 |
|---|---|---|---|---|---|---|
| debug  | 82580 | 2292 | 192 | 134400 | 85088 B (4.06%) | 0 |
| release| 58052 | 2000 | 184 | 134408 | 60256 B (2.87%) | 0 |

段布局与 GCC 一致：RW_IRAM1 @0x20000000 (0xE0C0=57536 B，栈顶 __initial_sp=0x2000E0C0，
8 KB 栈 + 512 B 堆在 DTCM 顶部)；RW_DMA_BUF @0x24000000 (256 B, UNINIT)；
RW_CAM_BUF @0x30000000 (76800 B, UNINIT)。两段 load base = RW 数据末尾，即无 Flash 载荷。
`fromelf -d` 无 BKPT（无半主机）。
