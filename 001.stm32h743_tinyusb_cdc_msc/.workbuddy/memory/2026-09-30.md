## 全面格式化第二轮（闭括号换行 + 4 空格 + int→int32_t + 构建/烧录验收）

用户指出"改动不全面"的根因：SKILL.md §2 只写了"开括号换行"，**没写闭括号也要换行**，导致单行体函数 `bool sdcard_present(void){ return g; }` 被漏改；且多数文件实际是 2 空格缩进（非规则要求的 4 空格）。

### 执行（全部 token 一致性 + 幂等双保险）
- 11 个自研 .c 用 `tmp_brace_fmt.py` 全部转 Allman（开/闭括号均独占一行），跳 `#` 行与 `= {` 初始化表与类型定义；栈记录 skip 属性。
- `tmp_reindent.py`（括号感知：跨未闭合 `(` 冻结 depth 保护多行签名）→ 2 空格体全部归 4 空格。**修了一个 bug**：原实现闭括号继承 body 缩进（落到 4 空格而非列0），改为行首连续 `}` 缩进 = `depth - 前导闭括号数`，闭括号回到列0 与开括号同列。
- `int→int32_t` 统一（排除契约）：main.c `int n`+`(int)`强转、sd_app.c `int n`、bsp_log.c `uart_write(int len)`+`int written`+`int n`+`(int)`强转、bsp_sdcard.c/.h `sdcard_read/write_blocks` 返回值。保留：`_write`/`main`（libc 契约）、`syscalls.c`(newlib 桩)、`disk_interface.c`(FatFs diskio)、`char` 字符串缓冲。
- `msc_disk.c` 因 brace_fmt 把多行签名的 `{` 错放到对齐列、体仍 2 空格 → **整体重写**（Allman + 4 空格 + 多行签名续行对齐到首参数列），与 git HEAD token 一致。
