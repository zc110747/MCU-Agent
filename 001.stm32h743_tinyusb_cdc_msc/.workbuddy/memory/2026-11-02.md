# 2026-11-02 · 001.stm32h743_tinyusb_cdc_msc

## 需求
1. 底层收发缓存增大到至少 32 KB。
2. SD 卡：上电（USB 初始化前）读取系统区 + FAT 表并缓存 ≥128 KB；单次传输完成、收到移除命令时回写同步。

## 落地
- `app/tusb_config.h`：`CFG_TUD_CDC_RX/TX_BUFSIZE` 512 → **32768**（tu_fifo 上限 0x8000，正好卡边界）；
  `CFG_TUSB_MEM_SECTION = section(".ram_d1")`，MSC 的 32 KB EP buf 移到 AXI。
  ⚠️ CDC FIFO 在 TinyUSB 里是 `_cdcd_itf[]` 成员，**没有** MEM_SECTION 属性 → 仍在 DTCM(.bss)，
  DTCM 因此涨到 64%（84224 B / 128 KB）。这是特性不是漏配。
- `bsp/bsp_sdcache.c|h`（新增）：128 KB / 256 扇区，64 组 × 4 路，`set = lba % 64`；
  数据窗口 + 32 KB 合并暂存放 `.ram_d1`(NOLOAD)，标签数组留 DTCM。
- `bsp_sdcard.c`：块层分叉 —— `sdcard_read/write_blocks` 走缓存，`sdcard_raw_*` 供缓存填充/回写/预热。
  **必须在块层内部路由**：msc_disk 的 read-modify-write 若读走缓存、写直通卡，会把旧扇区刷回覆盖新数据。
- 预热：解析 MBR → 分区 BPB → 预载 **系统区 72 扇区（MBR 8 + 引导区 64）+ FAT 184 扇区**。
  坑：本卡 rsvd=2226 扇区，按「part_lba+rsvd」整段预载会把 128 KB 窗口全吃掉、FAT 一个扇区都进不来，
  必须给系统区设上限（`SDC_SYSTEM_MAX 64`），且 MBR 段与引导段要分开取（BPB 在 part_lba=8192，不在 0）。
- 回写点：WRITE10 结束（只刷本次范围）、SYNCHRONIZE CACHE(0x35)、START STOP UNIT eject、
  FatFs CTRL_SYNC、tud_umount/suspend。脏扇区按 LBA 合并成多块写。
- CDC 回显改成按读入整块批量写：32 KB 突发回环 **6 KB/s → 314 KB/s**（原来逐字节 1 包/字节）。

## 实测（COM7 / G: 30 GB FAT32）
- `scache`: prewarm 256(系统 72 / FAT 184)；写 1 MB 后 `45 hit 13 buffered 2048 direct`，
  `writeback 16 ops / 58 sectors`。
- 写 176 B + 1 MB → **复位冷启动**后 `ls` 仍在（176 / 1,048,576），证明回写真落卡。
- `flood 500` = 500 行 32 KB 在 **3 ms** 内吞完。
- Debug FLASH 75364 B(3.59%) / DTCM 84224 B(64.26%) / RAM_D1 196704 B(37.52%)；Release 63900 B(3.05%)，双构 0 warning。
- `tools/test_cache.py write|verify|cleanup` 走 write→复位→verify→cleanup 三段，用「冷启动后文件还在」作为落卡判据。

## 「插入后打开 U 盘要 10 s」定位（结论已归档 README 5.3）

分段形态（三次复现，均一致）：

```
插入 -> 盘符出现        0.22 s   (主机只读 MBR+BPB，枚举 91 ms)
盘符 -> 可列出根目录     9.5 s   (主机按 32 KB 步长顺序读完 FAT 区，约 8 MB)
单条 READ10 设备侧       3 ms
单条 READ10 主机侧节奏   37 ms    <- 34 ms 在 USB 传输上
```

- **瓶颈是 USB Full Speed 12 Mbps（0.84 MB/s），不是 SDIO。**
  `sdbench` 直测（绕过缓存与 USB）：512B 1.95、4KB 6.80、16KB 10.07、**32KB 10.96 MB/s**
  —— 25 MHz × 4 线已跑到理论 12.5 MB/s 的 88%，8 MB 卡侧只要 0.75 s。
  SD 在单条命令里只占 3/37 ≈ 8%，把 SDIO 提到 50 MHz 也只是 9.66 s → 约 9.5 s。
- 已排除：**不是缓存未命中**（卡侧本来就 3 ms）；**不是 FAT 脏标志**
  （`FAT[1]=0x7FFFFFFF` bit31=0 时会让 Windows 校验全表，但用「安全弹出」写回干净位后重插**仍然 9.5 s**）。
  → Windows 每次挂载都会读这 8 MB，与 dirty 无关。
- 唯一有效的两条路：卷改 exFAT（FAT 1 MB → 约 1.5 s）/ FAT32 改 32KB 簇（→ 约 4.7 s）/
  外接 ULPI PHY 跑 HS（→ 约 0.3 s）。用户选择**暂不改**（卡上有数据，不能格式化）。

本轮新增的可复用能力：

- `sdbench [MB]` / `fatclean`（CDC 命令）、`mtrace` 增 `RDDONE`（arg=耗时 ms）与
  `SCSIDONE`、`USBFIRST`（首个 GET_DESCRIPTOR = 枚举起点）。
- `tools/watch_mount.py [--unplug] [秒]`：同时记录 CDC 端口出现 / 盘符可列出 / 首文件可读，
  并回读设备侧事件表。**判据必须用「能 listdir」而不是 GetLogicalDrives** ——
  拔线后 Windows 会保留盘符挂载点，用它做基线会导致永远等不到「新盘符」。
- 观察通道：**COM19 = 板子 USART1（ST-Link VCP）**，与 USB 无关，插拔 USB 期间持续可用；
  `tud_mount_cb` 里打的 `[N ms] USB configured` 可把设备 tick 与墙钟对齐。
- 事件环扩到 768 条、读预算 384，`g_tr` 放 `.ram_d1`（DTCM 只有 128 KB，别再加）。
