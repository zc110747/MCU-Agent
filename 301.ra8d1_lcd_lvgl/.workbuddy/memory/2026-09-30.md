### F5 联调修复（用户实测反馈后）

- ❌ `spawn pyocd ENOENT`：pyocd 只装在 workbuddy venv（`~\.workbuddy\binaries\python\envs\default\Scripts`），
  VSCode 继承的 PATH 没有它 → **已用系统 Python 装 pyocd 0.45.1**（`D:\software\Python3\Scripts` 已在 PATH）
- ❌ gdb `load` 中止：elf 含 `.option_setting_ofs/sas/ns/s` + `.option_setting_data_flash_s`
  （@0x0300a100 / 0x0300a134 / 0x0300a200 / 0x27030080）。pyocd flash 只是警告跳过，**gdb load 直接 abort**。
  修法：linker 里给这 5 个输出段加 `(NOLOAD)`（FileSiz=0 → load 跳过）。
  ⚠️ `/DISCARD/` 无效（输入 section 被 `KEEP()` 引用，ld 不丢）；objcopy `--remove-section` 可行但会刷 4 条
  `empty loadable segment` 警告（破坏零警告铁律）→ 最终用 `(NOLOAD)`
- ❌ `flash erase sector timed out` / `Error finishing flash operation`：pyocd 默认 flash timeout 10s 不够 →
  `pyocd.yaml` 加 `flash.timeout.init=30 / erase_sector=60 / program=60`
- ⚠️ F5 前必须复位：`preLaunchCommands: ["monitor reset halt"]`；load 重写 flash 后不复位会跑飞（SIGSEGV/Default_Handler）。
  cortex-debug 的 `runToEntryPoint` = 临时断点 + `startCompleteForReset`(复位) + continue，语义等价
- 改 linker 后 Ninja **不会自动重链**（`-T script.ld` 未被依赖跟踪）→ 必须 `rm build/firmware.elf` 再 build
- ✅ 最终实测：load → 复位 → 命中 `entry()` main.c:15，栈帧 Reset_Handler startup.c:71，单步进 bsp_led_init

### Round 3：`Failed to launch PyOCD GDB Server: Timeout.`

- 根因：cortex-debug 1.12.1 内置启动就绪正则 `/GDB server started (at|on) port/`，
  而 **pyocd 0.45.1 输出的是 `GDB server listening on port 50000`** → 永不匹配 → 超时
  （且 pyocd 日志**全走 stderr**：实测 stdout 0 字节 / stderr 2710 字节；cortex-debug 的 `onStderr`
  同样做 initMatch，所以不是流的问题，就是正则问题）
- 修法：`"overrideGDBServerStartedRegex": "GDB server (started|listening) (at|on) port"`（两种措辞都匹配）
- 排查手法备忘：`grep -rhoE "initMatch=.{0,140}" ~/.vscode/extensions/marus25.cortex-debug-*/dist/*.js`
  可直接挖出扩展内置正则；错误 `Failed to launch <X> GDB Server: <msg>` 来自 `server.on("launcherror")`
