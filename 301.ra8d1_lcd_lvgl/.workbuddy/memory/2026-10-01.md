## ★★★ 黑屏根因定位与修复（Phase 5 最大卡点，已解决）★★★

### 症状
2 寸 MIPI 屏**始终纯黑**（有背光）；`lcd dsi` 报 `link_status=0x0000`（IDLE，非 video mode）；
启动日志 **44 条 DCS 命令全部 timeout**（`[mipi] timeout waiting for cmd 0x..  (seq0=0)`），
44×100ms = **白白浪费 4.4 秒启动时间**。

### 根因（一句话）
**`R_MIPI_DSI_Open()` 从未被调用** → DSI 外设完全未初始化 → 面板无视频数据。

### 根因（完整链路）
`R_GLCDC_Open()` 的收尾处有这样一段（`r_glcdc.c:440`）：
```c
#if defined(GLCDC_CFG_USING_DSI)
    glcdc_extended_cfg_t * p_extend     = (glcdc_extended_cfg_t *) p_ctrl->p_cfg->p_extend;
    mipi_dsi_instance_t  * dsi_instance = (mipi_dsi_instance_t *) p_extend->phy_layer;
    err = dsi_instance->p_api->open(dsi_instance->p_ctrl, dsi_instance->p_cfg);
#endif
```
即 **DSI 必须由 GLCDC 的 open 代劳打开**（RA8 手册 R01UH0995 §56.3.1：DSI 要在 GLCDC 配置之后开）。
而 `GLCDC_CFG_USING_DSI` 是否定义，取决于 `Drivers/renesas/fsp/inc/instances/r_glcdc_cfg.h`：
```c
/* 我们原来的（错） */
#if (RA_NOT_DEFINED != RA_NOT_DEFINED)   // ← 常量与自身比较，恒假！
#define GLCDC_CFG_USING_DSI
#endif
```
这是 **FSP 生成器模板占位符未被替换**——本该是 `#if (RA_NOT_DEFINED != 1)`（官方 MIPI 版写法），
结果实例名被替换成了 `RA_NOT_DEFINED` 字面量出现在**等号两边**。

**证据**：官方两个工程对照
| 工程 | 条件 | 结果 |
|---|---|---|
| 官方 `vision_board_mipi_2.0inch_lvgl` | `RA_NOT_DEFINED != 1` | ✅ 真 → 开 DSI |
| 官方 `vision_board_rgb_4.3inch`（无 DSI） | `RA_NOT_DEFINED != RA_NOT_DEFINED` | ❌ 假 → 跳过 |
| **我们** | `RA_NOT_DEFINED != RA_NOT_DEFINED` | ❌ 假 → **DSI 从未打开** |

→ **本工程误用了 RGB 4.3"（无 DSI）版本的 `r_glcdc_cfg.h`。**

### 修复（一行）
`Drivers/renesas/fsp/inc/instances/r_glcdc_cfg.h`：`RA_NOT_DEFINED != RA_NOT_DEFINED` → `RA_NOT_DEFINED != 1`
（并加注释警告不要复制回 RGB 写法）。

### 修复前后硬件实测对照（SWD 读寄存器）
| 寄存器 | 修复前 | 修复后 | 含义 |
|---|---|---|---|
| `NVIC ISER0` | `0x00000005` | `0x000001FD` | DSI 的 irq3~8 全部使能 |
| `DSILINK.LINKSR` | `0x00000000` | `0x00000100` | **VRUN=1 视频模式运行中** |

### 诊断方法论（可复用，重要）
1. **`IELSR[]` 的偏移是 `0x6300` 不是 `0x0`**（`R_ICU.IELSR[96]` @ 0x6300，`R7FA8D1BH.h:10528`）。
   按 0x0 读 ICU 会得到全 0 的假象，差点误判"ELC 未编程"。**读寄存器前先查 struct 注释里的 `@ 0x...` 偏移。**
2. **间接调用（函数指针）在 `arm-none-eabi-nm` 里不产生符号引用**——
   `dsi_instance->p_api->open(...)` 编译成 `blx r3`，`nm | grep mipi` 是空的，
   但**反汇编 `R_GLCDC_Open` 能看到 `39a: blx r3`**。判"某调用是否编进"要看反汇编，不能只看 nm。
   反之，判"宏屏蔽是否生效"（整段代码消失）才用 nm。
3. **`-dM -E` 预处理直接看宏是否定义**，比反复重建快得多：
   `arm-none-eabi-gcc <整套 -I> -dM -E src.c | grep <MACRO>`
4. **`bsp_irq_cfg()` 只写 IELSR**；`R_BSP_IrqCfg/CfgEnable()` **不写 IELSR**，只设 NVIC 优先级+context+使能。
   两者独立——所以"NVIC 使能了但 IELSR 是 0"这种组合是可能的（反之亦然）。
5. RA8D1 Vision Board 是 **flat 工程**（未定义 `_RA_TZ_SECURE`/`_RA_TZ_NONSECURE`）→ `BASE_NS_OFFSET = 0`，
   外设直接用 `0x4000_xxxx` / `0x4034_xxxx`，无 NS 影子地址。
6. 探针可信度自检：SRAM 写读回 + NVIC IPR（`R_BSP_IrqCfg` 必写）双确认后再信外设读数。
   `0x220F0000` 超出 RAM（RAM = `0x22000000 + 0xE0000`），会触发 SWD FAULT ACK。

## 301.ra8d1_lcd_lvgl：Phase 5 触摸（CST812T）排查 —— 判定硬件层故障

### 结论

## Phase 7：取消触摸 + 单页信息界面 + 硬件 RTC 实时时钟（完成）

### 决策依据
用户指令："触摸应该是不支持的，先取消实现，只是构建单页面，显示当前的硬件信息和实时时间更新即可"；
时间源经 AskUserQuestion 澄清 → 用户选 **硬件 RTC 真实时钟**（非运行时长）。

### 关键事实（RTC）
- 原理图 p3：**Y2 = 32.768kHz/9pF** 接 XCIN(J15)/XCOUT(J14)，负载电容 C23/C24=15pF（已贴）→ 硬件 RTC 可行。
- `cfg/bsp_cfg.h`：`BSP_CLOCK_CFG_SUBCLOCK_POPULATED=1`、`SUBCLOCK_STABILIZATION_MS=1000`。
  启动期 `bsp_clock_init() → bsp_sosc_init()` **已启动并稳定子时钟**（SOSCCR.SOSTP=0）。
- FSP 树**无 `r_rtc`**（本地+官方 BSP 全无）→ **手写 `bsp/ra8d1-vision-board/bsp_rtc.c/.h`** 直接编程 `R_RTC @ 0x40202000`。

### RTC 寄存器（`R7FA8D1BH.h`，struct @12774 起，size 0x80）
- 0x00 R64CNT；**0x02 RSECCNT**；0x04 RMINCNT；0x06 RHRCNT；0x08 RWKCNT；0x0A RDAYCNT；0x0C RMONCNT；0x0E RYRCNT(16bit)
- **0x22 RCR1**；**0x24 RCR2**（bit0 START/bit1 RESET/bit2 ADJ30/bit3 RTCOE/bit6 HR24/bit7 CNTMD）；**0x28 RCR4**（bit0 RCKSEL/bit7 ROPSEL）
- 计数器为 **BCD**（一 nibble 一十进制位）。
- `R_SYSTEM_BASE = 0x4001E000`（**不是** 0x40203000！）；`PRCR` @ +0x3FA，解锁值 **0xA502**（PRC0|PRC1）。

### ⚠️ 最大坑：`RCR4.RCKSEL` 语义与字面相反
| RCKSEL | 选择 |
|---|---|
| **0** | **子时钟（32.768kHz 晶振）** ✅ |
| 1 | LOCO（内部低速 RC，未校准） |

初版误置 1 → RTC 跑 LOCO，**实测快 10.63×**（60.61s 真实时间走 644s）。
置 0 后 60.61s 实走 60s（ratio 0.9899）。

### ⚠️ 取证坑：不要用 SWD 读 RTC
`0x40202000` 位于 **VBATT 域**，SWD APB 直读常返回 0（RCR2/RCR4/RSEC 全 0），
**不能据此判"RTC 未启动"**；用串口 `rtc info` 前后差值测走时（=唯一可靠判据）。

### ⚠️ 新坑：SWD halt/resume 会让 SCI9 shell **失聪**
调试器 halt 核心后，串口 msh **不再回显/收命令**（heartbeat 仍打印，tick 前进）。
`verify_phase7.py` 若崩溃在开 SWD 之后、未 `t.close()`，会把板子留在 deaf 态 → 后续串口检查全 FAIL。
**修法**：SWD 连接放脚本最后；跑前列 **reset** 板子恢复 shell；脚本崩溃后手动 reset。
（这与旧笔记"serial 先于 pyOCD 打开"是同一族问题的强化版。）
