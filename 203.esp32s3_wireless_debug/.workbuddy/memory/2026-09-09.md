# 2026-09-09 · 203.esp32s3_wireless_debug（ESP32-S3 CMSIS-DAP 探针）

## 主线：消除 JTAG `Error: Invalid ACK (4) in DAP response`（已彻底解决，未提交 git）

用户现象：Sysprogs OpenOCD 走 `transport select jtag` + `target/stm32h7x.cfg`
能"找到芯片但数目不对"，随后 `Error: Invalid ACK (4) in DAP response`（ACK=4 即 FAULT/无效）。

### ★ 最终根因（build7 修复）—— C 的 bool 提升把 TDI 钉死为高

`components/jtag/jtag.c` 原宏：
```c
#define PIN_TDI_OUT(v) pin_out(TDI_GPIO, (v))       /* ← 致命 */
```
`pin_out(int gpio, bool high)` 的第二参是 **bool**，C 把**任何非零值提升为 true**。
`jtag_sequence()` 直接把整个移位寄存器字节 `i_val` 传进去（未掩码），
于是**只要该字节剩余位非零，TDI 就恒为高电平，真实 LSB 被忽略**。

后果链：`IR = DPACC(0x0A) = 0b1010` 被移出成 `0b1111 = BYPASS(0x0F)`
→ TAP 进 BYPASS，DPACC 扫描读回垃圾 → ACK=4 FAULT。

**为什么 IDCODE 阶段却是对的**：OpenOCD 在 TAP 发现阶段送的 TDI 位流恰好**全 0**，
字节为 0 → bool 为 false → TDI 低，侥幸正确。所以"能找到芯片、后续全 FAULT"。

修复：
```c
/* MUST mask to bit 0 — pin_out() takes bool, C promotes ANY nonzero to true. */
#define PIN_TDI_OUT(v) pin_out(TDI_GPIO, (((v) & 1U) != 0U))   /* jtag.c:142 */
...
JTAG_CYCLE_TDIO(i_val & 1U, bit);   /* jtag.c:321  mask: TDI is bit 0 only */
```

### ☆ 关键认知：OpenOCD 根本不走 `DAP_JTAG_Transfer(0x17)`

Sysprogs OpenOCD 0.12.0 的 JTAG 传输**全部用 `DAP_JTAG_Sequence(0x14)`** 由主机逐位构造
DPACC/APACC 扫描，`0x17` 只在别的实现里用。
→ 所以 build6 时 HID 直发 `0x17` 已 `ack=1 OK`、IDCODE=0x6BA00477 全对，
**OpenOCD 却依然 FAULT**：真正跑的是 `0x14` 这条路径。
**教训：先确认对端实际调用的是哪条命令路径，再修。**

### 其余 3 个真实缺陷（顺带按 ARM 官方 JTAG_DP.c 逐位移植修正）

1. **Shift-IR 差一拍**：Shift-IR 状态下链在**每个 TCK 上升沿**都前进，**包括离开 Shift-IR 的那一沿**。
   最后一位必须与 `TMS=1` **同一个边沿**打出（该沿既移位又跳 Exit1-IR）。
   旧实现把所有位在 TMS=0 下打完、再补一拍做 Exit1-IR → **多移一位，IR 错位**（0x0A→锁存 0x0D）。
2. **多 TAP `after` deskew 是多余的**：官方 DR 扫描无 deskew——因为 `TMS=0` 循环先在 TDI 上打 `index` 拍
   bypass，同时把更靠 TDO 的 TAP 已捕获位冲出，之后直接读即可。旧的 `after` 偏移 + `uint64_t tdo` 累积是错的。
3. **ABORT 有独立 IR = 0x08**，不是 DPACC。`dap_jtag_write_abort()` 补 `jtag_ir(JTAG_IR_ABORT)`。
   `jtag.h` 新增：ABORT 0x08 / DPACC 0x0A / APACC 0x0B / IDCODE 0x0E / BYPASS 0x0F。

### 排错弯路（记录以免重犯）
- build4 试"IR 改 LSB-first"：IDCODE 0 变 `0xFFFFFFFE`（原 MSB-first 是 `0x58B24001`）→ 位序非唯一根因。
- build5 试"多 TAP 顺序反转 [after][selected][before]"：IDCODE 0=`0x00000000`、1=`0x4892C000` → **反转推理是错的**。
- 结论：停止猜测，**直接下载 ARM 官方 `CMSIS_5/CMSIS/DAP/Firmware/Source/JTAG_DP.c` 逐位对照移植**才收敛。

## 可复用铁律
- **凡是把"整字节/整寄存器"传进 `bool` 形参的引脚宏，必须掩码 `& 1U`**——C 的非零→true 提升会静默钉死电平。
  这类 bug 只在数据非零时暴露，全 0 测试向量永远测不出来。
- JTAG Shift-IR/Shift-DR 的**最后一位与 TMS=1 同边沿**；补一拍就是多移一位。
- 手写 JTAG 状态机不要靠推理，直接对照 ARM 官方 `JTAG_DP.c` 逐位移植。
