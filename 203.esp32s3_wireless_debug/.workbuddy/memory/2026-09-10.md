- 现象：上电日志到 `W (1014) gpio: conflict found for GPIO[4]` / `GPIO[5]` 就没了，

## 用户指令：AP 默认不开，USB 优先（因"目前一直 USB 通讯错误"）
### 根因
`CONFIG_DEBUG_ENABLE_WIFI` 存在于 Kconfig 但**从未被任何代码使用** → wifi_dap 无条件启动；
ESP32-S3 上 Wi-Fi RF 一旦工作就破坏 USB OTG HID 传输时序，主机侧表现为 CMSIS-DAP 通讯错误。

### 实现（已完成，构建零警告 + 烧录验证）
- `components/usb_device`：新增 `usb_device_is_connected()`（= **`tud_mounted()`**）
  与 `usb_device_vbus_present()`（= `tud_connected()`）。
- `main/app_main.c`：USB 优先仲裁——上电先起 USB，在 `CONFIG_WIFI_DAP_USB_WAIT_MS`（默认 3000 ms）
  内轮询；主机枚举完成 → 常驻 USB 模式，**完全不碰 esp_wifi**；超时无主机 → 才 `wifi_dap_init()`。
  仲裁结果用 **ESP_LOGW** 输出（WARN 级才可见）。
- `components/wifi_dap/wifi_dap.c`：`wifi_dap_init()` 用 `#if !CONFIG_DEBUG_ENABLE_WIFI` 门控；
  两条启动日志提到 W 级。
- `components/wifi_dap/Kconfig`（新建）：`WIFI_DAP_USB_WAIT_MS`。
- `sdkconfig`：`CONFIG_DEBUG_ENABLE_WIFI=y`、`CONFIG_WIFI_DAP_USB_WAIT_MS=3000`。
- `main/CMakeLists.txt`：**放弃** `if(CONFIG_DEBUG_ENABLE_WIFI)` 条件化 REQUIRES
  （本 IDF 版本在组件注册阶段取不到该 CMake 变量 → 静默丢 include 路径 → `wifi_dap.h: No such file`），
  改回无条件 REQUIRES，运行时门控交给 C 层 `#if`。已在文件内注释说明原因。

### ★ 坑：tud_connected() ≠ 有主机
初版用 `tud_connected()` 判定，结果 PN 上**根本没有 VID_303A 设备**却打印 "USB host detected"。
在 ESP32-S3 上 `tud_connected()` 只代表 **VBUS 存在**（插充电头/充电宝也为真），
必须用 **`tud_mounted()`**（主机完成 SET_CONFIGURATION）。改后实测 `vbus=1 mounted=1`。

### 真机验证（COM21）
- 串口：`W (1362) probe: USB host enumerated (vbus=1 mounted=1) -> USB mode, Wi-Fi AP NOT started`
- 热点：改前 `ESP32-DAP-A118` 广播；改后 `netsh wlan show networks mode=bssid | grep ESP32-DAP` → **0**
  （Windows 扫描有缓存，需等 20–30 s；可配合 `tools/hold_reset.py` 关联确认归属）。
- USB 链路：`openocd -f tools/verify_usb_hid.cfg`（新建）→
  `CMSIS-DAP: FW Version = 1.2.0`、`Serial# = 441BF6FFA118`、`Interface Initialised (SWD)`、`Interface ready`；
  末尾 `Error connecting DP: cannot read IDR` 是**没接 STM32 目标板**的预期结果，USB HID 通讯本身正常。
