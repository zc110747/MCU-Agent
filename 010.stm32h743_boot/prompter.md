# 实现基于u盘(qspi flash)的升级功能

实现支持内部qspi-flash虚拟成u盘，支持检测u盘内文件，判断hash和版本满足，且和内部不一致支持升级功能。

1. 支持qspi-flash通过tinyusb虚拟成u盘功能，启动时挂载fatfs，支持读取内部文件，处理完之后自动移除，支持后续tinyusb访问u盘
2. 检测到文件、长度、版本号、HMAC-SHA256计算值，所有固件共用同一套密钥，写入到代码中；支持降级，检测到HMAC-SHA256计算值正确且和内部不一致，即可允许升级，更新app地址区域。
3. 启动时，根据系统配置区的升级信息进行代码区域检查，所有条件正常(通过HMAC-SHA256、版本号计算和常规跳转检测，如堆栈地址是否符合要求)，满足则复位使用过的硬件模块，然后跳转执行，默认延时(包含校验时间)，且USB未连接状态，连接后时u盘模式，此时不进行跳转，计数清零

## 硬件资源(详细原理图见附件，直接解析补充)

1. 芯片STM32H743ZIT6，外部无源晶振25MHZ
2. 支持调试串口，连接PA9/PA10，接入stlink串口中
3. FLASH内部数据格式

0x08000000 ~ 0x08020000：bootloader地址(本软件)
0x08020000 ~ 0x081DFFFF: app地址，代码需要再0x08021000区域固定存放4字节的版本号(1.0.0.5，每一项值都是1~99)
0x081E0000 ~ 0x081FFFFF: 系统配置区(存放升级信息，还有其它配置参数)

4. 支持运行LED，再bootloader内部200ms快速闪烁，测试应用中1s闪烁
5. usb已经连接，使用fs模式

## 注意事项

1. 升级文件格式

- 升级文件stm32h7_xx.bin(xx可以指代具体项目)
- 配套信息verify.json

```json
// 示例
// 版本号值每一项都是0~99
{
    "name": "stm32h7_xx.bin",
    "len" : 323232,
    "HMAC-SHA256" : "xadaddad",
    "version": "1.0.0.1"
}
```

可先使用简单文件测试，tools目录下提供工具生成上述文件格式和验证文件，进行全流程验证

2. flash在升级过程中要考虑cache问题，mpu要确保此区域读写不通过cache，写入后进行读取校验
3. 如果项目超过10分钟解决同一问题，且无额外信息进展，则停止运行并通知人工介入
4. 参考已经安装的嵌入式开发相关skills，提高效率

## 建议流程

1. 完成qspi-flash的访问读写和tinyusb的移植支持虚拟u盘功能(内部需要支持fatfs，启动检测不满足文件系统格式化，满足进行升级检测力促)
2. 实现对于内部flash的读写接口，用于升级做准备
3. 使用Fatfs读取内部文件，存在完整升级包和verify.json文件时，进行解析判断是否满足升级要求，满足则进入flash升级流程完成全部功能，不满足直接退出
4. 进行校验是否允许跳转，不满足则停留在bootloader中，满足则延时8s进行跳转(需要满足usb未连接条件)，拔出usb不需要恢复跳转，等待下次复位才进行跳转

## 验收标准

1. 代码完成后进行调试仿真，每个阶段都进行相应的测试后，满足再进入下一个阶段(调试信息记录在log目录中)
2. 核心功能，虚拟u盘访问qspi flash、升级和安全校验、功能跳转需要完整支持
