## 日志接口替换：BSP_UART_Printf → bsp_log（PRINT_LOG）

用户需求：用 001 工程的 `bsp_log.c` 替换现有 `BSP_UART_Printf`，无真机，只需编译通过即可 commit。

### 动因
旧 `BSP_UART_Printf` 走阻塞式 `HAL_UART_Transmit(..., HAL_MAX_DELAY)` —— 每行日志按波特率占满整帧时间（115200 下 110 B ≈ 10 ms）。boot 路径上跳转前的 8 s 窗口被这些死时间灌满，QSPI/USB 时序不好推理。

### 落地
- 新增 `bsp/bsp_log.c` + `bsp/bsp_log.h`（从 001 移植，剥离项目特定描述）：`printf_log` / `vprintf_log` / `PRINT_LOG()` 宏 / `log_uart_tx_irq` / `log_uart_init` / `bsp_log_init`；`PRINT_LOG_ENABLE` 置 0 时全部编译期消除。
- `bsp/uart.c/h` 退化为**兼容层**：保留 `BSP_UART_Init()`（转调 `bsp_log_init()`）、`BSP_UART_SendStr/SendBuf`、`g_uart_log` RAM 镜像；新增 `BSP_UART_LogMirror()`。镜像改为由 `vprintf_log()` 喂入，**所有**输出字节都进镜像（比原来只镜像 Printf 更完整）。
- 94 处 `BSP_UART_Printf(` → `PRINT_LOG(`，覆盖 app/main.c、app/boot.c、app/upgrade.c、app/fs_init.c、app/qspi_test.c、bsp/msc_qspi.c、test_app/app/main.c。
- 两个 `stm32h7xx_it.c` 加 `USART1_IRQHandler(){ log_uart_tx_irq(); }`。
- `test_app/` 补 `CMakeLists.txt`（原先缺失，README 4.2 的构建命令实际跑不起来）：排除根 `app/main.c`+`app/stm32h7xx_it.c` 避免 main/SysTick_Handler 重复定义，复用 `bsp_log.c`/`uart.c`/`syscalls.c`/`led.c`；`syscalls.c` 必须带上否则链接报 `_sbrk`/`_write` 等 undefined。

### 决策记录（为什么没删）
- `g_uart_log` **保留**：`capture.py` 按符号名 dump（`LOG_SIZE=0x4000=16 KB`，与 `UART_LOG_BUF_SIZE` 一致），删掉会静默失效。
- `BSP_UART_Init/SendStr/SendBuf` **保留**：`SendBuf` 是字节级输出口，删了要重写调用方；`Init` 保持 void 调用以不打扰调用方契约。
- 未启用 newlib-nano / `-u _printf_float`：本工程无浮点打印，省 ~1.5 KB Flash，也免动链接脚本。

### 本次踩到的 armlink / Keil 移植坑（重要，已沉淀进 stm32-build-and-scaffold skill）
1. **armlink 不支持嵌套 load region**：`UPGRADE_RAM_LOAD LR_IROM1 { ... }` 报 `L6630E`/`L6226E`/`L6292E`。
   → 必须改**独立顶层 load region** + 显式基址：`LR_UPGRADE 0x0801E000 0x00002000 { UPGRADE_RAM 0x24000000 ... }`。
2. `+RG` 属性必须**逗号分隔**：`*( +RW, +ZI )`，写成 `+RW +ZI` 直接 parse 失败。
3. 段选择器要带点：`*.o (.upgrade_ram)`；裸写 `*(UPGRADE_RAM)` 报 `L6231E: Missing module selector`。
4. **区域符号名取自「执行域」名**：执行域叫 `ER_UPGRADE` 就得引用 `Image$$ER_UPGRADE$$Base`。改成 `UPGRADE_RAM` 后才对上 `Image$$UPGRADE_RAM$$Base`。
5. `UNINIT` 只能挂在执行域，挂 load region 会 `L6324W`。
6. **多 load region 时 `fromelf --bin` 会输出「目录」**（每个 region 一个文件），要单镜像必须 `--bincombined`。
7. `CFG_TUSB_OS=OPT_OS_NONE` 下 TinyUSB 要求应用提供 `tusb_time_millis_api()`；GCC 靠 `--gc-sections` 把 `tusb_time_delay_ms_api` 整段摘掉所以从没暴露，**Keil 无此兜底**必须真定义。
8. `bsp/syscalls.c` 必须**从 Keil 排除**（否则 newlib 的 `_sbrk/_write/__io_putchar` 与 `mdk_target.c` 的 `__use_no_semihosting` 冲突）；反向地 `mdk_target.c` 必须**保留**。这是"链接能过、运行时才撞 `BKPT`"的延迟暴露型故障。
9. 镜像里 61 个 `BKPT` opcode **不是**半主机泄漏，是 TinyUSB `TU_BREAKPOINT()` 读 `CoreDebug->DHCSR` 的守卫（仅挂着调试器才真断）；实测半主机 `SVC 0xAB` 为 **0**。
