## LCD 显示重叠 / 边沿未覆盖 BUG 修复（bsp_lcd.c）
- 现象：界面能显示、字库能挂载，但中间文字重叠、边沿没覆盖。
- 根因 1（重叠）：`lcd_color_fill/lcd_set_cursor/lcd_fast_drawpoint` 误把 `setxcmd+1/+2/+3` 当连续寄存器写；但 0x2A/0x2B/0x2C 是 MIPI-DCS 命令码，必须"命令写一次 + 跟 4 个数据字节"。原写法把 CASET 数据拆散写进 PASET(0x2B)/RAMWR(0x2C)，地址窗口错乱 → LVGL 每块渲染带写到错误 GRAM 区 → 重叠。
- 根因 2（边沿未覆盖）：`lcd_scan_dir` 在 MV=0（不转置）时仍把 lcd_width/height 从 800x400 互换成 400x800 → `lcd_driver_clear` 按 400x800 开窗只清左半屏。已改为仅 MV=1 才互换，并让 `lcd_driver_clear` 显式开全屏窗口(0..w-1,0..h-1)。
- 修复后双构建零警告：Debug FLASH 225380B、Release FLASH 259436B（bss 547KB 主要在 SDRAM）。用户自行烧录 COM5 验证。

## FatFs 死锁 BUG 修复（字体挂载阶段卡死）
- 现象：固件启动到 `[FONT] mounting U-disk fonts` 后卡死，串口停在 `[FONT`，中文字库无法加载。
- 根因：**两个 FreeRTOS 任务并发访问同一 U 盘的 FatFs**。
  - `file_task`(idle+2) 在 `g_usb_state=USB_MOUNTED` 后仍长时间跑 `usb_disk_explore()`（写 demo 文件 + 递归遍历 dump 全部文件），持续做 FatFs 读写。
  - `ui_task`(idle+2) 见 USB_MOUNTED 立即调 `lcd_driver_font_init()`，里面又 `f_mount(&g_lcd_fs_info.fs,"0:",1)` 用**另一个 FATFS 工作区重新挂载同一盘**，并随后 f_open 字体文件。
  - 底层 `disk_read/disk_write`(usb_host_app.c) 用单个全局 `_disk_busy[0]` 标志 + `wait_for_disk_io` 自旋等 MSC 完成回调。两任务并发置 `_disk_busy[0]=true` → 完成回调清错标志 → **丢唤醒 → 一方永久自旋**，盘 I/O 整体卡死。
- 修复：
  1. `usb_host_app.c` 新增 FreeRTOS 互斥量 `xFsLock`，`fs_lock()/fs_unlock()` 串行化所有 FatFs 入口；`file_task` 的 `f_mount`+`usb_disk_explore` 整段加锁（在 usbh_app_init 创建）。
  2. `bsp_lcd_text.c`：`lcd_driver_font_init` 去除多余 `f_mount`（盘已由 file_task 挂载，再挂会换掉 FATFS 工作区指针）→ 仅 `fs_lock` 包住 f_open 循环；`font_read_raw` 的 f_lseek+f_read 也加 `fs_lock`（覆盖 LVGL 渲染期取字）。
  3. `usb_host_app.h` 导出 `fs_lock/fs_unlock` 原型。
- 真机验证 PASS（COM5 抓取）：`[FONT] font status mask = 0x1E`（GBK12/16/24/32 全开，UNIGBK.BIN bit0=0）。**不再卡死**，字库挂载成功。
- 关键结论：**UNIGBK.BIN 非渲染必需**。`lv_font_gbk.c` 经编译期表 `lv_gbk_map.c`(`lv_gbk_from_unicode`) 做 Unicode→GBK，再读 GBKxx.FON 取字模；UNIGBK.BIN 仅被打开、渲染路径从未读取。故 mask=0x1E 即可正常显示中文，缺 UNIGBK.BIN 无害（可忽略）。
- 双构建零警告：Debug FLASH 225240B、Release FLASH 259296B（bss 547KB 主要在 SDRAM：LV_MEM 256KB+FreeRTOS 堆 512KB+LVGL 绘制缓冲 96KB）。
