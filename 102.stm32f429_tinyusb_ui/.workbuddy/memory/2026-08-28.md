# 2026-08-28 — 第二版：TIM7 时基 + microSD(SDIO) + 启动加载器

## 需求（用户原话拆解）
1. HAL 时基 TIM11 → **TIM7**；已有 FreeRTOS（堆在 SDRAM）保留
2. LVGL 作为**独立任务**显示处理，缓存在 SDRAM（核对后确认第一版已满足）
3. 增加 **SD 卡读取**，读取失败再等 USB 读取，成功后加载字库
4. LVGL：默认界面只有**英文、内部 ascii**，居中 `wait for system start...`；
   字库加载成功 → 主界面（设备状态信息）；**超时 10s** → 居中 `sdcard and usb loader failed!`
5. OpenOCD + ST-Link 真机验证

## 实现
- `app/stm32f4xx_hal_timebase_tim.c` 重写为 htim7；`stm32f4xx_it.c` 换 `TIM7_IRQHandler`
  （TIM7_IRQn=55，**独立向量**，启动文件 vector 470 已有；TIM11 需与 TIM1 TRG/COM 共用）
- 新增 `bsp/bsp_sdio.c/.h`：PC8-12 + PD2 AF12，4-bit，**轮询不接 DMA**，ClockDiv=2 → 卡时钟 12 MHz
  （SDIOCLK 48 MHz = PLLQ=7，与 USB 同源）
- 新增 `app/fs_diskio.c/.h`：统一 diskio 胶水（pdrv0=USB MSC / pdrv1=SDIO）+ `fs_lock` 互斥量；
  SD 路径对**未对齐 4 字节**的缓冲区经 `s_sd_scratch[512]` 中转（HAL 内以 uint32_t* 读 FIFO）
- 新增 `app/sd_card.c/.h`：SDIO init + `f_mount("1:")`，失败不锁存（可重试），`sd_card_set_quiet()`
- `bsp/bsp_lcd_text.c`：`lcd_driver_font_init(const char *vol)` 参数化卷前缀（"1:"/"0:"），
  新增 `lcd_driver_font_source()`；切换卷前 `f_close()` 旧文件 + `lv_font_gbk_reset_cache()`
- `app/app_ui.c`：新增 `app_ui_show_centered()`（清屏 + 单条居中标签，纯 ASCII 走编译期字表）
  + `ui_teardown()`（**必须先 `lv_timer_del()` 再 `lv_obj_clean()`**，否则定时器持悬空 lv_obj_t*）
- `app/ui_task.c`：启动加载状态机（见 README §3.2.1）
- `FF_VOLUMES` 1 → 2；`HAL_SD_MODULE_ENABLED` 开；CMake 加 `hal_sd.c` + `ll_sdmmc.c`
- 新增 `tools/verify_serial/verify_boot_flow.py`（17 项 pass/fail）、`capture_reset.py`

## 本轮踩的三个坑（都已修，见 README §6.1）
1. **UART TX 环形缓冲溢出静默丢日志**：`UART_TX_BUF_SIZE` 仅 512 B 且 `uart_write()` 满即丢弃，
   而 `file_task` 全量 dump 3 MB 字库/JPG 长期占满缓冲 → 新增日志时有时无、已有日志缺字节。
   修复：缓冲扩到 **2048**；dump 加两道闸（>2048 B 文件只列不 dump；整轮预算 16 KB）。
2. **SD 空卡槽刷屏**：每 500 ms 打一次 `SDIO init FAILED`。修复：`sd_card_set_quiet()`，
   首次失败后静音，10s 后探测降频到 3s（热插拔恢复保留）。
3. **超时页重复触发**：deadline 分支写成 `s_state != LOAD_OK`，但 `LOAD_FAILED` 同样满足 →
   每 5ms 打印一次。修复：改为 `s_state == LOAD_BOOT`。

## 调试技巧
- `capture_reset.py` 只复位不烧录，抓控制类日志；改了代码后**必须先烧录再抓**，否则跑的是旧固件
  （这点坑了一次：修完重复打印后只跑 capture_reset，看到的还是旧行为）。
- 想复现「无介质」场景而 U 盘又拔不掉时，用编译开关 `-DCMAKE_C_FLAGS="-DXXX=0"` 单独建一个
  临时 build 目录，测完删掉。
- SDIO 无卡时 `HAL_SD_Init()` **不会**跑满 `SDMMC_MAX_VOLT_TRIAL`(65535)：`SD_PowerON()` 在
  第一个 CMD55 无响应即 return，单次失败 <1 ms，可以放心轮询重试。

# 第三版（2026-08-28 晚）：电容触摸 + 双页面 + I2C2 传感器

## 需求
1. 主界面底部加 LVGL 左/右图标按钮循环翻页
2. 第 2 页显示硬件信息（AP3216C + MPU9250）
3. GT9147，模拟串行总线（T_CS=PI8 T_MOSI=PI3 T_MISO=PG3 T_SCK=PH6 T_PEN=PH7），
   初始化要打印访问 ID 是否满足
4. T_PEN 中断 → FreeRTOS 信号量 → 触摸任务检测

## ★ 最重要的一条硬件结论：这块"模拟 SPI"实际是 I2C
- **GT9147/GT911 数据手册只有 I2C 接口，没有 SPI 模式。**
- 排针丝印的 SPI 名字与真实信号对应关系（与正点原子 `ctiic.h` / `gt9147.h` 逐针对上）：
  `T_SCK(PH6)=CT_SCL`、`T_MOSI(PI3)=CT_SDA`、`T_CS(PI8)=CT_RST`、`T_PEN(PH7)=CT_INT`、
  `T_MISO(PG3)` 未用。
- 所以 `bsp/bsp_sw_i2c.c` 实现的是**位绑定 I2C**（开漏+上拉，~165 kHz，DWT 忙等时序）。
- **板上实贴芯片是 GT911 不是 GT9147**（`product ID = "911" (addr 0x14)`），寄存器兼容。
  但 184 B 配置块是 9147 专用的，**绝不能给 GT911 上传** —— 代码里只在 ID 恰为 "9147"
  且版本 <0x60 时才上传。
- GT911 自报分辨率 **480×800**，与本项目 GRAM 窗口 / LVGL 画布完全一致 → 恒等映射。

## 实现
- `bsp/bsp_sw_i2c.c/.h` 位绑定 I2C；`bsp/bsp_gt9147.c/.h` 驱动；`bsp/bsp_touch.c/.h`
  服务层（EXTI + 信号量 + 映射）；`bsp/lv_port_indev.c/.h` LVGL pointer indev
- `app/touch_task.c` 任务；`app/sensor_task.c` 采样任务；`app/app_ui.c` 双页面 + 导航条
- HAL：开 `HAL_EXTI_MODULE_ENABLED` + 编 `stm32f4xx_hal_exti.c`；`stm32f4xx_it.c` 加
  `EXTI9_5_IRQHandler` → `HAL_EXTI_IRQHandler(&g_touch_exti)`
  （本 HAL 版本**没有** `HAL_SYSCFG_EXTILineConfig`，SYSCFG EXTICR 由 `HAL_EXTI_SetConfigLine`
   写；`HAL_EXTI_RegisterCallback` 无需额外宏即可用）

## 本轮踩的四个坑（都已修，见 README §6.1）
1. **`canvas 1x1`**：touch_task(idle+4) 比 ui_task(idle+2) 先跑，`g_lcd_info` 还是清零状态。
   修：`bsp_lcd.c` 加 `lcd_driver_ready()`（在 `lcd_config_init()` 末尾置位），
   `bsp_touch_init()` 等它（≤10s），`bsp_touch_scan()` 里再刷新一次几何，双保险。
2. **UI 布局硬编码 800×480，实际画布是 480×800** → 横向被裁 320 px、纵向空 320 px。
   修：布局全改从 `lv_disp_get_hor_res/ver_res()` 取。（注意：这是**行为变更**，
   之前画面是裁过的，现在才是铺满。）
3. **MPU9250 `-3` 被当整包失败**：`-3` 只代表 AK8963（经 MPU 内部 I2C master）读失败，
   加速度/陀螺其实是好的。修：单独 `mag_ok` 标记，退避 30s→2s，错误每 60s 最多打一次。
4. **首条错误日志被吞**：限流哨兵用 `0xFFFFFFFFU`，`s_round - 0xFFFFFFFF` 回绕成 2
   永远 <120。修：哨兵改 `0` + `*last_at == 0U` 短路。

## 验收
- `verify_touch.py`（交互式，需人工点屏）与 `verify_touch_irq.py`（全自动 7/7 PASS）
- 启动流程回归 `verify_boot_flow.py` 17/17 PASS，无退化
- 双构零警告：Release FLASH 302,244 B(28.82%) / RAM 30,296 B(15.41%)；

## ★ 调试技巧：无需手指即可验证 EXTI 链路
`EXTI->SWIER`（0x40013C10）写 1 会产生与引脚边沿**完全等价**的中断请求。
用 OpenOCD 在启动完成后 `halt` → `mww 0x40013C10 0x80` → `resume`，即可端到端验证
"EXTI→NVIC→ISR→信号量→任务唤醒"。已封装成 `tools/verify_serial/verify_touch_irq.py`。
（这只验证链路，不验证引脚电平，仍需手指点一次确认。）
