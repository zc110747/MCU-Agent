### 设计要点（已贯穿全程）
- SYSCLK=168MHz（非180）：HSE25 → PLL M25 N336 P2 Q7 → 168MHz/48MHz USB（180MHz下PLLQ需7.5非法）
- HAL 时基 TIM11（中断号 TIM1_TRG_COM_TIM11_IRQn）；SysTick 归 FreeRTOS；二者独立
- SDRAM(W9825G6KH-6, FMC Bank1) 先于任何 FreeRTOS 对象初始化；heap_5 单区 0xC0000000，链接 NOLOAD
- TinyUSB 0.21.0 Host MSC；diskio 胶水在 app/usb_host_app.c；tuh_msc_mount_cb 用普通 xSemaphoreGive（任务上下文，非ISR）
- USART3 PB10/PB11 115200 调试口；LED0=PB1 心跳，LED1=PB0 USB状态；BEEP=PCF8574 P0，ETH复位=PCF8574 P7；I2C2 PH4/PH5
- USB_DISK_AUTO_FORMAT=0（默认不自动格式化，避免误清U盘数据）

### 关键修正：USB 初始化时序（用户指令，2026-08-26 深夜）
- **问题根因**：原 main.c 在 `vTaskStartScheduler()` **之前**调用 `USBH_HW_Init()`（使能 OTG_FS 中断）+ `tusb_init()`（启动协议栈、开始产生中断）。OTG_FS ISR 调用 FreeRTOS `xQueueSendToBackFromISR`/`xSemaphoreGiveFromISR`，这些 FromISR API 仅在调度器运行后合法 → 中断在 RTOS 未就绪时触发，破坏系统，导致跑飞/无后续输出。
- **修正**：将 `USBH_HW_Init()` + `tusb_init()` 移入 `usbh_host_task()` 入口（while 循环之前），即 OS 启动后执行。`usbh_app_init()`（建信号量+file_task）仍留 main()（仅建对象，不碰 USB 硬件）。`usb_host_app.c` 新增 `#include "bsp_usb_hw.h"` 与 `extern void Error_Handler(void)`。
- **双构建零警告复验**：Release FLASH 68,176B(6.50%)/RAM 15,792B(8.03%)，Debug FLASH 58,296B(5.56%)/RAM 15,776B(8.02%)，SDRAM 堆 512KB，均 0 警告。
- **真机验证（PASS，COM5 串口实测）**：OpenOCD 烧录修正固件后，COM5(USART3 PB10/PB11,115200 8N1) 抓到完整链路：
  `System Init → I2C/PCF8574 init OK → SDRAM Init OK → FreeRTOS Heap configured → Waiting for USB disk... → USB Host Init（出现于 Waiting 之后！证实时序修正生效）→ USB Disk Connected → Mounted → Create/Write/Read test.txt → 回显内容 → USB Disk Ready → Heap object @ 0xC0002F38（证实堆在 SDRAM 0xC0000000）`
  → U 盘枚举+test.txt 端到端、SDRAM/FMC 运行态、USB 初始化时序 三项均转为**硬件验证 PASS**。
- **产出**：`verify_serial/flash_com5_test.py`（先开 COM5 → OpenOCD 烧录 reset run → 抓 12s → 特征串判定），一键复测。
- **文档闭环**：README §3.1（初始化顺序图+USB 时序约束说明）、§6 验收表、§7.5 串口实测；ACCEPTANCE_REPORT §1/§4.3/§6/§7/§8 全部将"待硬件验证"改为"真机 2026-08-26 PASS"。
- **结论**：此前 COM5 "0 字节" 实为 USB 初始化时序 bug 导致固件跑飞（非接线问题）；修正后 COM5 正常输出。故本板 COM5 即 USART3，无需再怀疑接线。

### U 盘内容经串口读取并打印（2026-08-26 深夜，新增功能 + 真机 PASS）

- **实现**（`app/usb_host_app.c`）：

  - `dump_chunk()`：非打印字符（除 `\r\n\t`）替换为 `.`；**关键**：用 `uart_write(out, j)` 显式传长度，不用 `uart_puts`（见下方 bug）。
  - 可选 `USB_DISK_SEED_DEMO`（默认 1）：挂载后向 `0:/demo/`（含子目录 `sub/`）写 hello.txt/notes.txt/world.txt，使读取打印可被一键复测；置 0 即纯读用户盘。

- **FatFs 兼容性坑**：本工程 FatFs R0.15 的 `FILINFO.fname[]` 直接存长文件名（统一缓冲区），**无 `lfname`/`lfsize` 字段**（与 ChaN 新版不同）→ 初版用 `fno.lfname` 编译报错，已改为直接用 `fno.fname`。
- **🔴 Bug 修复（uart_puts 长度陷阱）**：原 `dump_chunk` 把 `out[64]` 填满 64 字节后调用 `uart_puts(out)`；而 `uart_puts` 内部用 `strlen`，满 64 字节无 `'\0'` 终止符 → `strlen` 越界读到栈垃圾，在 64 字节块边界**插入乱码**（实测 `FreeRTOS`→`FreeRl<0x02>TOS`）。改用 `uart_write(out, j)` 显式长度后干净。教训：**向 uart 输出定长缓冲务必用 `uart_write` 而非 `uart_puts`**。
- **双构建零警告复验**：Release FLASH 72,120B(6.88%)/RAM 15,200B(7.73%)，Debug FLASH 61,292B(5.85%)/RAM 15,176B(7.72%)，SDRAM 堆 512KB。
