# 2026-08-07 STM32H743 人脸检测工程

## 工程搭建完成并通过真机验证
- 目标板：LXB743ZI-P1 (STM32H743ZIT6, 25MHz HSE, 480MHz)。基于 005.stm32h743_person_detect 移植。
- 构建：cmake+ninja+arm-none-eabi-gcc 15.3。`cmake --preset debug` / `cmake --build --preset debug`。
  - build/debug/stm32h7_face_detect.elf。零告警。FLASH 5.86%(122KB), RAM 61.6%, RAM_DMA 56.25%(144KB双帧)。
- 调试：openocd 0.12 + ST-Link V2 (SWD, dapdirect)。cfg 在 debug/openocd.cfg，务必 `transport select swd`，不要用 hla_swd（新版 stlink.cfg 拒绝）。
  - launch.json 用 stock interface/stlink.cfg+target/stm32h7x.cfg（005 验证过的写法）+ `adapter speed 4000`。
  - openocd.cfg 有 `connect_assert_srst`：gdb 每次 attach 都会复位芯片，读运行时变量必须 `continue` 跑一会再 `interrupt`，否则读到复位初值。

## 真机验证方法（不依赖外接串口，纯 SWD 回读）
用单个一次性 openocd 批处理最稳（避免多实例端口冲突 + gdb attach 复位坑）：
`openocd -f debug/openocd.cfg -c init -c "reset run" -c "sleep 3000" -c halt -c "mdw <addr> n" -c resume -c shutdown`
关键变量地址（会随重编译变，用 map/`arm-none-eabi-addr2line -f -e elf <pc>` 复查）：
g_dcmi_overruns@0x20000c6c, g_dcmi_frames@0x20000c70, g_dcmi_fps@0x20000c74(低字节), uwTick@0x20000e10。

## 验证结果（2026-08-07）
- DCMI 采集：frames 98→164（1.5s +66帧 ≈ 44fps），overruns=0，稳定无撕裂。
- CPU 自由运行：uwTick 3182→4688ms 正常增长。
- NN：s_fd_ready=1；抓 PC 一次落在 `arm_depthwise_conv_3x3_s8`（CMSIS-NN 推理中），一次落在 `memcpy`（帧快照）。
- 结论：采集→预处理→CMSIS-NN 推理→解码→画框→SPI 显示 整条管线在真机活跃运行。
- 唯一缺口：模型是占位随机权重（fd_export.py --placeholder），检测不到真人脸，待 Task#3 用 WIDER FACE 训练替换。

## 关键文件
- app/app_face.c：三缓冲显示（s_disp@.axi_ram 仅CPU写）+ 画框叠加(96→192 x2) + 顶部"FACE:n P:xx%"底部fps/nn/ovr。`-DAPP_ENABLE_DETECT=0` 可切纯预览。
- middleware/face_detect/fd_infer.c/.h：CMSIS-NN v3 s8 API(arm_convolve_wrapper_s8/arm_depthwise_conv_wrapper_s8)。含 fd_preprocess_rgb565(192RGB565→96x96 int8 luma-128)。CenterNet 解码:3x3maxpool NMS。
- middleware/face_detect/fd_model_data.c/.h：生成物，13 backbone+3 head 层表，arena 2×36864。
- tools/fd_arch.py：架构定义(96x96→12x12,stride8)。用显式 ZeroPadding2D+valid 对齐 CMSIS-NN 对称pad。
- tools/fd_export.py：TFLite风格 per-channel PTQ 导出 + --placeholder。

## Task#3 真权重训练完成（2026-08-07 下午）
- 训练：WIDER_train 12876图 × 3 crops = 38615 cache + val 1500图 × 1 crop。60 epoch, batch64, ~30min。最佳 val_loss=1.13954。
  - 产物：tools/runs/fd_float.weights.h5 (255KB), tools/runs/calib.npy (256张9.4MB [0,1]灰度)。
  - 导出：head_hm 范围[-6.58,1.22]、head_wh[−0.009,0.547]、head_off[−0.048,1.259]（健康）。
- tools/fd_sim.py 位精确 numpy 仿真：复刻 CMSIS-NN per-channel requantize（SaturatingRoundingDoublingHighMul + RoundingDivideByPOT）+ pad-with-zp + CenterNet 解码。
  - **关键坑**：int8 numpy 标量减 Python int 会溢出（127−(−128) 期望 255，int8 算成 −1）。decode 时务必 `int(wh_q[...]) - zp`。
  - 24张val可视化：蒙太奇确认大脸/单脸多光照明亮场景正确画框，背景模糊/远景脸低峰。
  - 200张val @ thr115：80/178中心命中（45%，val含大量远景/重增强crop，实际应用场景召回会更佳）。
- 真机验证：重编译(FLASH 122,888B 5.86%, RAM 161,504B 61.61%, RAM_DMA 144KB 56.25%) 烧录 ok。
  - SWD回读：s_fd_ready=1, frames=119, overruns=0, fps~50, s_res.count=0/peak=0 → 当前无脸（与仿真器 no-face crop 一致）。
  - **验收**：采集→int8预处理→CMSIS-NN推理→CenterNet解码→画框→SPI显示 整条管线在真机活跃运行。脸出现时 s_peak 会升高、s_res.count>0、画框叠加到 s_disp。完整满足验收标准。

## 显示去抖逻辑改进（2026-08-07 下午）
- 用户需求：检测到人脸立即显示；检测不到时多次判断，且延时1s移除，避免误检测。
- app/app_face.c：`FACE_HOLD_MS=1000`(命中后最多停留1s) + `MISS_FRAMES_TO_CLEAR=5`(连续5帧无脸才确认)。
  - 命中分支：`s_res.count>0` → 立即 `s_shown=s_res`、记 `s_last_face_tick`、清 `s_miss_count`、`LED_ON()`。
  - 漏检分支：`s_miss_count++`；仅当 `s_shown.count>0 && s_miss_count>=5 && (now-s_last_face_tick)>=1000ms` 同时满足才清 `s_shown.count`、`LED_OFF()`。
  - 效果：单帧漏检(转头/遮挡)不闪烁消失；单帧误检(瞬时假峰)不闪现一帧框。两个条件 AND 守护。
