## 全局变量 static 化 + 结构体化（mcu-code-style §2/§3/§4）

用户要求：所有文件级可变全局 → `static` + 分组进结构体；跨文件使用的单独函数接口暴露，暴露多的用结构体指针。例外：`const`（flash，不结构化）、HAL `*_HandleTypeDef`（保留 extern）。

### 落地（app/main.c, app/uvc_app.c, bsp/bsp_camera.c + 两 header）
- `bsp_camera.c`：~56 个 `cam_*` 文件级可变全局 → 8 个子结构体合进容器 `static cam_diag_t s_cam_diag`（stats/ctl/pin/bus/pull/regdump/snap/poke）；`cam_reg_addr` 改 `static const`（flash 例外，不进结构体）

- 跨文件引用检查：**无**候选全局被其它 .c 使用（仅 header 里为 SWD 读符号留了 extern 死声明）→ 全部删除死 extern，无需函数/结构体指针暴露

## 调试探针抽取(sys_prob) + 修复结构化丢失默认值导致 UVC 无画面

### 探针抽取（bsp/sys_prob.c/.h）
- `bsp_camera.c` 里的调试探针（pin/bus/pull/regdump/poke 五组 + 6 个探针函数 +
  16KB `trace[]` 缓冲）抽到独立 `bsp/sys_prob.c/.h`。
- 宏开关 `CAM_DIAGNOSTICS`：CMake `option(ENABLE_CAM_DIAGNOSTICS OFF)`，关闭时不编译
  sys_prob.c、不加宏 → 探针代码/数据完全不进链接。开启时 `.ctl.regdump_base=0x3800` 等
  默认值生效。
- 探针通过与 bsp_camera 的桥接接口（`bsp_camera_dvp_pins_mode/_pull`、
  `bsp_camera_is_auto_running/_stop/_restart_continuous`）借用采集管线。
- SWD 诊断状态以结构体指针暴露：`sys_prob_get_state()-><group>.<field>`，字段名沿用旧
  `s_cam_diag.<group>.*`。`bsp_camera_service()` 内 `#ifdef CAM_DIAGNOSTICS sys_prob_service();`。
- 内存影响（Release）：OFF FLASH 53024B / ON 71600B（+18.6KB）；RAM OFF 354KB / ON 371KB
  （+17.2KB，16KB trace 占大头，因 s_sys_prob 有非零初值落在 .data）。OFF 构建 nm 无任何
  `sys_prob*` 符号 → 隔离干净。

### 严重运行期 bug（静默，编译零警告）
**根因：结构化时 s_cam_diag 的初始化遗漏了两个非零默认值。** 原 HEAD 为
`cam_pclk_pol = 1` / `cam_crop_en = 1`，结构体化后 `.ctl` init 里没写，落到 0：
- pclk_pol=0 → DCMI 采样沿变 **FALLING**（传感器 0x4740=0x21 必须 RISING）
- crop_en=0 → DCMI 裁剪切窗被 service() 关闭 → 取整条 400px 行（240000B/帧 vs DMA 115200B）

DCMI 因此误判消隐 → DMA 从不驻留 → `bsp_camera_snapshot()` 每次 torn → 0 帧进 USB → **无画面**。
`uvc_app.c` 同样漏了 `fps_window_ms=1000U` / `interval_100ns=10000000/FRAME_RATE`（次要）。

**修复**：`s_cam_diag` 补 `.ctl.pclk_pol = 1U` / `.ctl.crop_en = 1U`；`s_uvc` 补两个默认值。

### 定位方法（无串口，纯 SWD + 主机侧）
- 用 `arm-none-eabi-nm` 取 `s_cam_diag`/`s_cam`/`s_uvc` 地址，OpenOCD `mdw` 读遥测：
  **`s_cam_diag.snap.snap_ok/snap_torn/snap_ndtr0/ndtr1` + `stats.frame_count/start_count` +
  `stats.words_per_frame` + `s_uvc.frames_sent/xfer_started/stream_poll_true/commit_count`**
  一次读全即可判断卡在哪一段（采集 / 快照 / USB 提交 / 主机协商）。
- 关键指纹：`frame_count>0` 但 `snap_ok==0 且 snap_torn==帧数` → 采集 OK，快照全废；
  再看 `words_per_frame`（2400 而非 28800）即可指向"裁剪切窗/同步沿不对"。
- 主机侧用 `ffmpeg -f dshow -i video="UVC Control"` 抓帧（本机 ffmpeg 在
  `/d/data/agent-tools/ffmpeg-master-latest-win64-gpl-shared/bin`）；PowerShell 工具吞 stdout，
  USB 设备清单改 `Out-File` 后再 Read。
- 修复前后实测：snap_ok 0→23、snap_torn 595→0、words_per_frame 2400→28800、
  frames_sent 0→4、ffmpeg 成功抓到 240x240 YUY2（画面正确）。

### 教训（可复用）
**全局变量合并进结构体重构时，必须逐项核对原文件级非零初始值并原样搬进 init；
编译零警告 ≠ 运行时正确。** 建议重构后对每个"有非零默认"的变量做 grep 对照
（`git show HEAD:<file> | grep -E "^(volatile|static).*="`）。本次即因漏核对，
把两个真实的硬件配置默认值静默清零。
