# 2026-09-28

## Reader 英文比中文小 — 根因与修复（已真机验证）

- 用户指令：① 放弃此前"未实施的字库重构"（GBK32 用于标题/GBK24 用于小字/禁用 GBK16），
  以当前工作版本（GBK16/24 进 PSRAM、GBK32 SD 缓存、Reader 默认 CN32）为**新基线**；
  ② 解决 Reader 读文件时英文比中文小的问题。
- 根因：GBK 字库文件只含双字节区 23940 字形（文件大小 766080=23940×32 已证明无 ASCII 余量），
  故混合文档里的英文落回 GBK 字的 fallback。原 fallback 被硬编码成内嵌 16px CJK 字
  (`lv_font_source_han_sans_sc_16_cjk`) → CN32 文档里英文只有 16px；且 `lv_draw_label.c:587`
  用**行字度量**算纵坐标、用**回退字形自身 box/ofs** 算高度，导致英文既小又偏下。
- 修复：自生成**满格位图 ASCII 字**（每字母塞 N×N 整格，与 GBK 同源列优先 1bpp 布局），
  编译进固件（main/ui/ascii_fonts.cpp，16/24/32 三档，共 ~22KB，不依赖 SD 卡）；
  把 16/24/32 GBK 字的 fallback 分别指向同尺寸 ASCII 字（满格/同基线/同格宽）。
  - 新增 tools/gen_ascii_font.py（Pillow 渲染 Montserrat-Medium → 列优先 1bpp）；
  - sd_font.cpp：Face 加 `ascii` 标志；`face_glyph_dsc` 增 ascii 分支(gid=cp-0x20)；
    新增 `install_ascii()`；`sd_font_install()` 挂载三档 ASCII 字并把 GBK 字 fallback 改写。
  - 关键坑：① ascii_fonts.c 被 C 编译器编译（含 namespace 报错）→ 改名 .cpp；
    ② 新增源文件须 `touch main/CMakeLists.txt` 触发 GLOB 重扫，否则链接期 undefined reference；
    ③ C++ `const` 命名空间变量默认内部链接 → 定义加 `extern`。
- 验证：零警告构建（exit 0，ebook_lvgl.bin 0x1c7000，app 分区余 56%）；flash COM14 成功；
  boot 日志 `installed ... ascii fallback: N px, 95 glyphs` ×3 + GBK16/24/32 安装 +
  `CJK font: card's GBK face` + `Returned from app_main()`（干净启动）。
- 待用户真机进 Reader 打开书确认：英文与中文同高、同基线、同格宽（视觉确认）。
