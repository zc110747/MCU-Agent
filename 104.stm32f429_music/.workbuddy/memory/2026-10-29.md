## 关键坑（已验证）
- **NT35510 是 480x800 面板**：MADCTL=0x00 时 GRAM 只有 480 宽，若把窗口设成 800 宽，X 地址越界回卷 -> 每行错位（图形能显示但错乱）。
  横屏必须 MADCTL(0x3600)=0xA0（MV=1 转置）+ 窗口 800x480；竖屏 MADCTL=0x00 + 480x800。
  正点原子 LCD_Scan_Dir 里的 dir 镜像表（横屏时 L2R_U2D -> D2U_L2R）就是干这个的。
- **openocd 一次性 `-c "init; reset run; shutdown"` 不可靠**：之后 PC 可能停在 0x1FFFxxxx(ROM)、USART1_CR1=0。可靠做法是 `program ... verify` + `reset halt`，再单独 telnet/gdb 下 `resume`。
- openocd 后台进程不能用 shell 的 `(&)` 启动（会话结束即被回收），要用工具的后台任务。

### 显示错乱根因（已修）
- NT35510 = 480x800；横屏必须 MADCTL(0x3600)=0xA0（MV=1）+ 窗口 800x480。
- 沿用 MADCTL=0x00 又设 800 宽窗口 -> X 越界回卷 -> 每行右移，表现为错乱。
- 参考实现：drv_lcd.c 的 lcd_display_dir() + 正点原子 LCD_Scan_Dir() 的 dir 镜像表。

### 音频倍速根因（已修）
- SAI 是 stereo master（2 slot/帧），曲库是 1 ch 单声道；原样喂数据 -> 每帧吃 2 个源采样 -> 2 倍速。
- 修法：wav_read_pcm() 增加 channels，单声道复制到两个 slot（16bit 就地反向展开；24bit 每采样写 2 个 32bit 字）。
- 验证：37 s 曲目实测 37.2 s（时间戳抓取），误差 <1%。

### 工具经验
- clang-format 可用 pip 装（本机在 python Scripts 目录）；仓库 house 配置见 002/003/004。
- 纯数据表/模板头不要格式化：lcd_ascii_font.c、lv_gbk_map.c、stm32f4xx_hal_conf.h、FreeRTOSConfig.h。
- **openocd 后台进程不能用 shell `&`**（会话结束被回收），要用工具后台任务；否则 gdb 报
  "could not connect (error 138)"。
- **gdb `detach` 不会 resume**：读内存前会自动 halt，读完后目标就停在那。
  想"读一下再让它跑"必须显式 `monitor resume`，否则表现为"tick 不涨/串口没日志"的假死。
- 抓串口要**先开抓取再复位**：启动日志只有 300~500 ms，抓取晚一步就全丢，之后播放期串口本就静默。

## 2026-10-29 追加：MP3 支持 + 文件计数 + 栈溢出修复

### 新增
- `third_party/minimp3/`（vendored，MINIMP3_ONLY_MP3 + NO_SIMD，单文件 `-mfloat-abi=softfp`）
- `app/mp3_decoder.c/.h`：ID3v2 跳过 + 自己分帧 + minimp3 解码，输出统一 16-bit stereo
- `app/track_decoder.c/.h`：按扩展名分派 WAV / MP3，播放引擎不再感知格式

- 播放任务栈 768 -> 1536 words（6 KB）

### 关键坑（已真机验证）
- **minimp3 的 `mp3dec_scratch_t`(16 256 B) 在栈上**：上游 `mp3dec_decode_frame()` 局部变量，
  3 KB 栈一点 MP3 立即 HardFault —— 这就是"点 MP3 死机"的真因。改 `static` 进 `.bss` + 栈提到 6 KB。
- **必须自己分帧再喂 minimp3**：整窗传入若尾部截断一帧，minimp3 会 `memset(dec,0,...)` 清掉
  Layer III bit reservoir，后续帧静默失败（实测 385 帧丢 87 帧，只播出 76% 时长）。
  自解析帧头 + `mp3_need()` 保证每次只喂完整一帧 -> 385/385，与 ffmpeg 相关性 0.999998。
- **调试器 halt 会打断 SDIO 传输**，之后 FatFs 每次 `f_open()` 都返回 `rc=1 (FR_DISK_ERR)`，
  整卷不可用到重新挂载。已在 `audio_task` 加"连续 3 首失败 -> playlist_clear + sd_card_invalidate"恢复路径。
