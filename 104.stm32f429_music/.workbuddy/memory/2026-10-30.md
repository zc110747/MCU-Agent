### 四个只有 armclang/armlink 才暴露的坑（都已写进脚本注释）

1. **启动文件不需要改向量表**。GCC 版脚本会把 DCD 改成 `vPortSVCHandler`，但
   `app/FreeRTOSConfig.h:96-98` 已把这些宏映射成 `SVC_Handler`/`PendSV_Handler`/`SysTick_Handler`，
   port.o 导出的就是 CMSIS 名字 → 改了就 L6218E Undefined。现在只复制 + 校验。
2. **`umfTarg=1` 让 uVision 忽略手写 .sct**，自动生成的 sct 没有 SDRAM 区 →
   L6406E 512KB 堆塞不进 192KB SRAM。必须 `umfTarg=0`。
3. **armlink 语法 `UNINIT` 要写在 size 前**：`RW_SDRAM 0x C0000000 UNINIT 0x02000000 {}`。
4. **补 `stm32f4xx_hal_flash_ex.c`**：GCC 靠 `--gc-sections` 丢掉未用的
   `HAL_FLASH_IRQHandler`，armlink 不做等价裁剪 → `FLASH_Erase_Sector`/`FLASH_FlushCaches` undefined。

### 最重要的一条：armclang 下自定义段不是 ZI

`sdram_heap.c` 原写法 `__attribute__((section(".freertos_heap")))` 在 armclang 下生成
**PROGBITS** 段（512KB 零），armlink 给它 LR_IROM1 内加载地址，`__main` 会在 FMC 初始化
**之前**把它拷到 `0xC0000000` → HardFault。`UNINIT` 只跳过 ZI 清零，拦不住 PROGBITS 拷贝；
AC6 6.14 也不支持 AC5 的 `__attribute__((zero_init))`。

判据：看 `Program Size` 的 `RW-data` —— 修之前 524640，修之后 352。

因为 GCC 链接脚本的 `.bss : { *(.bss*) }` 会抢先抓走 `.bss.*`（实测 RAM 溢出 406504 B），
最终按工具链分名：
- armclang → `.bss.freertos_heap`（NOBITS）
- GCC → `.freertos_heap`（GCC 对未初始化自定义段本来就是 NOBITS）
两侧链接脚本同时兼容两个名字（ld 不警告未匹配选择器，armlink 会报 L6314W，所以 sct 只列一个）。

> 顺带发现 102 工程有同样隐患：它 map 里 `.freertos_heap` 是 `COMPRESSED[204]` 的 RW 段，
> 也就是 512KB 零被压进镜像后运行时展开拷贝到未初始化的 SDRAM。102 未修。

### 新增文件

### 关键设计：SDMMC 独占靠"一直持有互斥量"

`fs_usb_session_begin()` = 先 `xSemaphoreTake(fs_lock)` 排空当前使用者，**然后不还**，
整场会话持锁 → 其它任何任务的 `fs_lock()` 必然阻塞。标志位方案只能挡住讲规矩的调用者，
挡不住已经进到 `f_read()` 里那个。配套：
- `fs_try_lock(ms)` 给可选读取方（GBK 字库）用，`fs_usb_session_active()` 时直接 RT_FAIL
  → 字形画成空白，不让 UI 任务阻塞整场传输。
- 会长时间用卡的音频流必须靠**自己的标志**提前撤：`audio_player_set_usb_mode(true)`
  → 在下一个 DMA 边界（44.1k/16bit ≈23ms）中断曲目、关文件、停 SAI → `parked=1`。
- 交接四步（顺序不能换）：mount 标志 → 通知播放器 → 等 parked（2s 超时强夺）→ 锁 FatFs。
  `s_owned` 最后才置 1，主机此前收到 `TEST UNIT READY=not ready` 自动重试，不会超时。

### 踩到的三个真问题

1. **容量别用 `f_getfree()` 硬算**：FF_FS_NOFSINFO=0 且 FSInfo 脏时会扫全 FAT，
   16GB 卡 ≈ 16MB 扇区 = 几十秒轮询 SDIO → 主机直接超时。改为读 `fs->free_clst`；
   未知且簇数 >64K 就显示 `TOTAL -- MB`，只在 ≤64K（FAT12/16 表 ≤128KB）时才退化扫描。
2. **SCSI 必须补 `SYNCHRONIZE CACHE(10)=0x35` / `VERIFY(10)=0x2F`**：TinyUSB 只内置
   INQUIRY/READ|WRITE(10)/READ CAPACITY/MODE SENSE/REQUEST SENSE/TEST UNIT READY/
   START STOP/PREVENT ALLOW。写已直落卡，这两条返回 0 即成功，否则主机在写路径上记错误。
3. **传输页文字只能 ASCII**：中文字形是绘制时现读 SD 的 `GBKxx.FON`，而此刻卡在 PC 手里
   → 只会画出空白（见上面 fs_usb_session_active 的快速失败）。
4. **切屏必须把旧屏 HIDDEN 掉**（`78d4b21`）：LVGL 8 的 `lv_obj_area_is_visible()`
   放行 `disp->prev_scr` 的失效请求，而 `prev_scr` 要等下一次 load 才清 → 只做
   `lv_scr_load` 的话，播放页 `LV_LABEL_LONG_SCROLL_CIRCULAR` 的曲名会持续往传输页
   刷脏区（花屏/残影）。隐藏在祖先上会被可见性检查直接拒绝。

### 断线与收尾

- 主判据 `tud_umount_cb()`，任务循环每 20ms 再查 `tud_mounted()` 兜底
  （漏事件也不会出现"卡被 PC 锁住、播放器永远拿不回来"）。
- 会话结束：`s_owned=0` → `fs_usb_session_end()` → `sd_card_remount()`（force=1 重读
  BPB/FAT，主机可能改过）→ `playlist_clear()` → 放开播放器 → 状态才回 IDLE
  （UI 看到 IDLE 才重开字库文件 + 清字形缓存，顺序反了会读到旧 FAT）。
