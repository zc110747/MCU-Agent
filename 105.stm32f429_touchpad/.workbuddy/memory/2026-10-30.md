## 23:30 真机联调（ST-Link 在线，本轮修了 2 个真 bug）

### 构建依赖整目录丢失
`Drivers/` 与 `third_party/` 在 105 里**完全不存在**（被仓库根 .gitignore 黑名单吃掉，
复制工程时静默遗漏），`cmake` 直接报 `No SOURCES given to target`。
已从 102 补 `Drivers/` + `third_party/{Fatfs,FreeRTOS-Kernel,lvgl}`（不含 lwip/mbedtls/tinyusb/audio）。
**连带后果**：`third_party/lvgl/lv_conf.h` 是随目录一起丢的，里面的工程专属配置必须重做：
`LV_USE_FS_FATFS 1` / `LV_FS_FATFS_LETTER 'S'` / `LV_FS_FATFS_CACHE_SIZE 512` / `LV_IMG_CACHE_DEF_SIZE 4`
（`LV_MEM_ADR 0xC0100000` 102 原版就有）。

### bug 1：SD 容量 32 位溢出（app/sd_card.c）
`sd_card_usage_mb()` 用 `uint32_t total_bytes = total_clusters * cluster_bytes`。
32 GB FAT32 卡：1946656 簇 × 16384 B = 3.19e10 B，mod 2^32 = 1.83e9 → 屏幕显示 **1744 MB**（已用 136 MB 同样是溢出差值）。
改为 `uint64_t`（只做 `>>20`，不需要 64 位除法）。修后显示 **30416 MB**，与 HAL `LogBlockNbr×512` 一致。
卡上 136 MB used 是真实文件占用（字库+壁纸之外用户自己存的），不是 bug。

### bug 2：SYSCFG 时钟没开 → 触摸完全失效（致命，bsp/bsp_touch.c）
`HAL_EXTI_SetConfigLine(EXTI_LINE_7, EXTI_GPIOH)` 写 `SYSCFG->EXTICR` 需要 SYSCFG 时钟，
工程里**没有任何地方** `__HAL_RCC_SYSCFG_CLK_ENABLE()`。
实测 `RCC_APB2ENR = 0x00000800`（只有 SDIOEN，bit14 SYSCFGEN=0）、`EXTICR2 = 0x00000000`
（EXTI7 仍映射 Port A）→ PH7 边沿永远进不了 NVIC，`touch_task` 永远等不到 `s_touch_sem`，触摸 100% 不可用。
修法：`touch_exti_init()` 开头加 `__HAL_RCC_SYSCFG_CLK_ENABLE()`。
修后 `EXTICR2 = 0x00007000`（Port H），`s_irq_count` 从 0 变 148→174（4 s 涨 26）。

### 本机调试套路（可复用）
- **`reset run` 在本机无效**（ST-Link 只接 SWD，NRST 没接）：目标一直停在 `0x08004ebc Reset_Handler`。
  必须走内核复位：`monitor reset halt` + `monitor resume`。
- `openocd -f openocd.cfg -c "...; exit"` 用完即退，目标会保持 halt —— 抓启动日志必须
  先开串口线程，再用 gdb 内核复位。→ 写成 `tools/serial_capture.py`。
- **不要用 gdb `call` 调固件函数**：会破坏 RTOS 上下文，之后 halt 常假报 `HardFault_Handler`
  （而 CFSR/HFSR 全 0）。判活靠连续读计数器变量（`s_loop_count` 15→56 / 3 s）。
- `SYSCFG_EXTICR[1]` 硬件偏移是 **0x4001380C**（0x08 是 EXTICR[0]，管 EXTI0–3），别读错。

## 23:55 改 USART1 + 串口命令通道 + 又修 2 个 bug

### 串口改到 USART1（PA9/PA10，AF7）
**实测这台机器上真正连着的是 COM3（CP210x），不是 COM13（CH340）**——CH340 是板载的但
PA9/PA10 没跳线过去。改完 USART1 后 COM3 立刻有日志。
- `bsp_uart.c/h`：`huart3→huart1`、`USART3→USART1`、`GPIOB→GPIOA`、`PIN_10|11→PIN_9|PIN_10`、
  `AF7_USART3→AF7_USART1`、`USART3_IRQn→USART1_IRQn`、`USART3_IRQHandler→USART1_IRQHandler`。
- RX 从"读 DR 丢弃"改成 **128 B 环形缓冲 + RXNEIE**，新增 `uart_read()`。
- APB1 42 MHz → APB2 84 MHz，BRR 由 HAL 自动算（实测 `CR1=0x202C`、`APB2ENR` 含 bit4）。
- 只在 `ui_task` 里解析命令（命令要调 LVGL，必须留在 UI 任务上下文）。

### 串口命令通道（单字符）
`c` 清屏 / `k` 换色 / `w` 换线宽 / `b` 壁纸 / `s`,`?` 状态 / `h` 帮助，其余回 unknown。
实现在 `app_ui.c: app_ui_command()`（`#if PRINT_LOG_ENABLE` 包住回显，Release 仍执行动作）。
工具：`tools/serial_verify.py`（12 条断言，`PASS 12 / FAIL 0`）、`tools/serial_capture.py`（抓启动日志）。

### bug 3：VTOR 从来没设过（致命，启动级）
`USER_VECT_TAB_ADDRESS` 在 `system_stm32f4xx.c` 里是注释掉的，工程隐含依赖"复位后 VTOR==0"。
一旦内核从 ST 系统存储器 bootloader 被拉起，VTOR=`0x1FFF0000`，而 **FreeRTOS
`prvPortStartFirstTask()` 是透过 VTOR 读初始 MSP 的** → MSP 被设成 bootloader 的值 → 首次 `svc` 崩。
症状：`CFSR=0x00018200`（PRECISERR|UNDEFINSTR），PC 停在 `prvPortStartFirstTask+30`，
串口只打到 `FreeRTOS heap: ...` 就再无任务日志。
修法：`startup_stm32f429xx.s` 的 `Reset_Handler` 开头显式 `SCB->VTOR = 0x08000000`（带 dsb/isb）。

### bug 4：UI 按 800×480 写死，屏实际是 480×800（显示级）
`[LCD ] active GRAM window 480x800 (panel spec 800x480)`——NT35510 + `DFT_SCAN_DIR=L2R_U2D`
下**活动窗口就是 480×800 竖屏**，102 的 app_ui.c 注释里也写明"什么都不按 800x480 硬编码，
布局从驱动报告的活动窗口推导"。105 把 `SCR_W 800 / CV_W 536 / BTN_W 188` 全写死了，
右侧 320 px 直接画到屏外。
修法：`app_ui.c` 全部常量改成 480×800 竖屏（画板 456×400 在上、手势面板 456×220 在下、
4 个按钮各 108 宽、footer 两行），并在 `app_ui_create()` 里加 `WARN layout is ...` 自检。

### 本机复位/抓日志的正确姿势（重要）
`reset run` 无效（NRST 没接）；`reset halt` 之后内核可能停在 bootloader。
**唯一可靠**：单次 openocd 会话手工装 flash 向量，再 resume：
```
openocd -f openocd.cfg -c "init; reset halt; reg sp 0x20030000; reg pc 0x<Reset_Handler>; resume; shutdown"
```
（`Reset_Handler` 地址用 `arm-none-eabi-nm` 从 ELF 取，不能写死。）
反复用 gdb `halt` 打断运行中的 RTOS 会制造假 HardFault / double-fault lockup，别据此下结论。



## 二期：改成 TinyUSB HID 鼠标（触摸板 + 三个玻璃键）

需求：触摸板滑动=鼠标移动，触摸区下面三个虚拟键=左/中/右，滚轮不做。
实现：`app/usb_mouse.c` + `usb_descriptors.c` + `tusb_config.h` + `bsp/bsp_usb_hw.c`；
UI 全部重写为触摸板布局（pad 456×380 / 三键 144×96 / 状态卡）。
串口命令改为 `l/m/r` 点键、`x/y` 移光标、`c` 清轨迹、`s` 状态、`h` 帮助。
`tools/serial_verify.py` 同时验证固件回显与主机光标位移，**PASS 17 / FAIL 0**。

### 三个必须记住的坑
1. **`tusb_init()` 不能放 main()**：它打开 OTG_FS 中断，如果 USB 已插着，中断会在
   `vTaskStartScheduler()` 内部触发 → `xQueueSendToBackFromISR` → FreeRTOS
   `vPortValidateInterruptPriority` 断言 → `Error_Handler`。必须放到 USB 任务第一行。
   现场 gdb 回溯：`OTG_FS_IRQHandler → dcd_event_bus_reset → osal_queue_send(in_isr) → assert`。
2. **TinyUSB 0.21 `TUD_CONFIG_DESCRIPTOR` 参数顺序变了**：`(config_num, itfcount, ...)`，
   config_num 在最前。按旧顺序写会让 `bNumInterfaces=0` → Windows 报
   **代码 10**，日志表现是读完 configuration descriptor 后直接 Suspend，
   **从不发 SET_CONFIGURATION、不请求 HID report descriptor**。
3. **CFG_TUSB_DEBUG=2 的 printf 很吃栈**：USB 任务栈 512 words(2 KB) 会溢出到
   `Error_Handler`，给到 1024 words 才稳。调试完记得改回 0。

### 其它实测结论
- `CFG_TUD_VBUS_DETECT_HW=0` 必须设：板上无 VBUS 分压，否则内核不认"已插入"。
- HID 按钮编号 1=左/2=右/3=中，报告位是 bit0=左、bit1=右、bit2=中（不是左中右顺序）。
- 触摸板用 UI tick 采样 `bsp_touch_get()`，不用 gesture 的 MOVE（有 2 px 量化，做鼠标发顿）。
- **SDIO 轮询 + USB 中断会打架**：`f_open` 偶发 `FR_DISK_ERR`，字库 mask 从 0x1F 掉到 0x0F。
  `lcd_driver_font_init()` 已加单文件重试 4 次（间隔 5 ms），实测恢复 0x1F。
- 主机侧验证不用 Add-Type（沙箱禁）：Python `ctypes.windll.user32.GetCursorPos` /
  `GetAsyncKeyState` 可用，能直接证明 HID 报告真的生效。
- 资源：Debug FLASH 240268 B(22.91%) / RAM 28592 B(14.54%)；
  Release 269656 B(25.72%) / 28600 B(14.55%)，双构零警告。
