# 2026-10-31 — 105.stm32f429_touchpad（USB 触摸板鼠标）

## 问题：触摸能用但"不跟手"

用户反馈光标跟随手指有拖尾/迟滞。定位后确认是**多处延迟叠加**，不是单一 bug。

### 量出来的基线（改之前）

| 指标 | 实测 |
|---|---|
| `app_ui_poll()` 循环频率 | **84 Hz**（≈12 ms 一轮，还会抖到 40 ms） |
| 鼠标 delta 计算位置 | 在这个 UI 循环里 → 光标采样率被它锁死 |
| HID 端点 `bInterval` | **8 ms**（主机 125 Hz 上限） |
| `TOUCH_POLL_MS` | 10 ms |
| `bsp_touch_scan()` 耗时 | 测出来 12.9 ms，**是假值**（见下） |

### 四个改动

1. **新建 `app/trackpad.c/.h`**：把"触摸采样 → delta → `usb_mouse_move_ex()`"整条
   链路从 `app_ui.c` 挪进 `touch_task`。UI 只消费视觉状态（圆点 + 64 点轨迹环，
   `trackpad_poll()` 带临界区读清标志，因为生产者优先级更高）。
   - `trackpad_set_area()` 由 `app_ui_create()` 注册；`app_ui_boot()` 时
     `trackpad_clear_area()`，splash 阶段样本全部忽略。
   - 语义变化：**一旦在 pad 内按下，滑出边界也继续跟随**（触摸板正常手感），
     但在按键上**按下**的那种接触永远不会进入追踪，所以不会误拖光标。
2. **HID `bInterval` 8 → 1 ms**（`app/usb_descriptors.c`）；`tud_task_ext(5)` → `2`。
   已验证配置描述符字节是 `... 10 00 01`。
3. **`TOUCH_POLL_MS` 10 → 5**，`TOUCH_RELEASE_POLLS` 3 → 4（20 ms 判定抬起，
   太紧会出现幻影 1 px 跳），`TOUCH_MAX_POLLS` 400 → 800（保持 4 s 上限）。
4. **加速度判档改成速度**：`usb_mouse_move_ex(dx, dy, dt_ms)`，阈值按
   "px / 10 ms" 算。采样率变了两次（84 → 172 Hz），按"每 tick 位移"判档会让同样的
   手速掉出高速档，表现为"越改越慢"。

[PAD ] feeds=2716 moves=0 clicks=0 drop=0

- 报告排队延迟 **1 ms**，端点忙 **0**
- `serial_verify.py` **PASS 17 / FAIL 0**（含主机侧 `GetCursorPos` 真实位移）

## ⚠️ 可复用教训：`bsp_delay_us()` 每次调用都清零 `DWT->CYCCNT`

原实现：

```c
void bsp_delay_us(uint32_t us) {
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
    DWT->CYCCNT = 0;              /* ← 每次调用都清 */
    ...
}
```

软 I2C 每个字节要调好几次它，于是任何"读两次 CYCCNT 求差"的耗时测量都被打成
垃圾：`bsp_touch_scan()` 明明 ~0.8 ms，测出来 12.9 ms，差点把我引到"优化 I2C"
的错误方向。**改成只启动一次、之后不再清零**。

> 判据：如果一个耗时测量结果大到"按这个值功能根本跑不起来"，先怀疑计时基准
> 被别人动过，而不是相信这个数字。

另外 `bsp_delay_us()` 里那三行寄存器写在软 I2C 的最内层循环里，本身就是浪费。

## 问题：触摸滑动完全不触发、状态卡"位移 X/Y"恒 0

上一条的 `[PAD ] feeds=2716 moves=0 clicks=0` **就是 bug 的早期证据**，当时被
读成"没触摸所以没位移"放过了。用户报"触摸不触发"后才回头对上：

```
[PAD ] feeds=10203 moves=0 clicks=865 drop=0
[MOVE] x=0 y=0
```

`feeds` 在涨（采样在跑）、`clicks=865`（触点被判成按了 865 次）、`moves=0`
（每次触点只拿到**一帧**坐标就被判松手 → delta 恒 0）。

### 根因：GT911 的空帧 ≠ 抬手

`0x814E` 的 **bit7 = 坐标缓冲已更新**，低 4 位才是触点数。
`bsp_gt9147_read()` 只取了低 4 位；5 ms 采样落在芯片 ~10 ms 报告周期的空档时读到
`0x00`，返回 0 个触点 → `touch_task` 当成 release → 笔画被切成单帧。
`GT_BUFFER_READY` 宏**早就定义了但从没被引用过**。

> 判据：只要"每次触点都只活一帧"且 `clicks` 与采样次数同量级，就是
> "空帧被当成抬手"这一类语义错误，不是 I2C/中断问题。

### 三层修法

| 层 | 值 | 语义 |
|---|---|---|
| `bsp_gt9147_read()` | `GT9147_NO_FRAME` (-2) | bit7=0，**不清状态寄存器**、不报 0 触点 |
| `bsp_touch_scan()` | `BSP_TOUCH_NO_FRAME` (-2) | 原样上传，`s_last_pressed` 保持不变 |
| `touch_task` | — | 空帧只 delay 后继续；距最后一帧 `TOUCH_STALL_MS=120` 才算丢失 |

`bsp_touch.c` 里加了 `#if BSP_TOUCH_NO_FRAME != GT9147_NO_FRAME / #error`，
防止两层哨兵值漂移。

### 连带修掉

- `TOUCH_MAX_POLLS` 800 → 3000：4 s 上限会把正常慢速拖拽判成
  `contact aborted` 并重新 rearm 中断（用户按住不动 4 s 就会看到日志）；
- abort 分支补 `trackpad_feed(0,0,0)`，否则指针逻辑上一直按着；
- **轨迹提交节流 `TRAIL_COMMIT_MS=60`**：原来每个点一次 `lv_line_set_points()`
  （一帧最多 24 次），而轨迹线覆盖 456×380 ≈ 350 KB 像素，NT35510 重绘 ~35 ms，
  手指一动 UI 就掉到 **13 Hz**，看起来像"界面不刷新"。改成点只进数组、每 60 ms
  提交一次，圆点仍每帧更新；空闲实测回到 **170 Hz**。

[MOVE] x=-403 y=60

## 问题：界面中文显示不全（部分汉字空白）

用户反馈状态卡区域中文没显示全。第一反应会怀疑"字库缺字"或"label 被裁"，
**都不是**。加 `f`（逐字自检）和 `k`（裸扇区读）两条命令后一次定位：

```
[FONT] 16px U+89E6 GBK=B4A5 FAIL seek=0 read=1 off=313280 got=0/32 slot=2
[FONT] check done: 118 CJK chars, map-miss=0 glyph-miss=354     <- 354 = 118x3 全灭
[SDIO] block 65536 -> 0  0E 0E 11 11 14 FF                       <- 裸读正常
```

判据链：
- `read=1` 是 FatFs `FR_DISK_ERR`，`got=0` 一个字节没读回来；
- **偏移 313 280 < 文件 766 080**，不是索引越界、不是字库被裁；
- `k` 裸扇区读当场成功 → 卡和 SDIO 控制器都好的，问题在 FatFs 收到 disk_read 失败。

### 根因：SDIO 数据通路失败后不自恢复（用户直接点出这一条）

`bsp_sdio_read_blocks()` 一次数据块传输失败后**只返回错误**，SDIO 的 DPSM 停在数据
状态，之后每条命令都失败 → 首次抖动之后字形读取永久报废。用户提示"读取失败重试
两次，且调用 Abort 复位"，正是正解。

修法：
- 读/写两侧都是「失败 → `HAL_SD_Abort()`（内部 CMD12）→ 重试」，最多 2 次
  `SDIO_RW_RETRIES`；
- 等卡回 `HAL_SD_CARD_TRANSFER` 超时也先 Abort，别把卡留在忙状态；
- **重试只放一层**：`font_read_raw()` 保持单次。两层叠加会把一次卡死放大成
  3×3 次 1 s 超时，UI 直接冻结几秒。

修后：`map-miss=0 glyph-miss=0`，三个 `.FON` 大小都等于完整 GBK 期望值。

> 可复用：**"字库缺字"先量文件大小与偏移，再谈缺字。** `.FON` 布局是
> 126 lead byte(0x81..0xFE) × 190 trail 槽 = 23 940 字形，索引
> `(qh-0x81)*190 + ql'`；16 px 每字 32 B → 766 080 B。第一次按 190×94 估期望值
> 会误报 "TRIMMED"，白跑一轮。

> 可复用：**外设层失败一律先 Abort 再重试**。SD/MMC 的 DPSM、USB 的端点、
> 软 I2C 的总线锁死都是同一类问题——错误返回后状态机没复位，重试必然全灭，
> 表现成"第一次偶发、之后 100 % 失败"。

资源：Debug FLASH 244 108 B(23.28%) / RAM 29 632 B(15.07%)；
Release 271 912 B(25.93%) / 28 992 B(14.75%)，双构零警告。提交 `70bf5b7`。

用户真机确认：**界面中文显示完整、触摸滑动跟手、长按不断**。本阶段收尾。

## SDIO 接收改 DMA + 一键编译脚本 / MDK 工程

### 一键构建
- `build.bat [debug|release|all|clean]`：CMake+Ninja；Release 自动带
  `-DENABLE_PRINT_LOG=OFF`（README 4.x 约定，日志格式串约 7 KB）。
- `build_mdk.bat [debug|release|all|gen]`：先 `gen` 生成 `.uvprojx` 再 UV4 -b。
- 两个脚本都用 `findstr`/`tools/mdk_size.py` 报 FLASH/RAM/SDRAM 占比，
  尺寸缓存在 `build*/size.txt`（增量构建时 `Program Size` 行不出现）。

### MDK 工程两处致命细节
- **`RvdsVP` 必须 = 2** 才是 "Single Precision"（1/3/4 都不开 FPU）。不开时
  FreeRTOS `portable/GCC/ARM_CM4F/port.c` 的 `__VFP_FP__` 守卫直接编译失败。
  试过 `-mfpu=fpv4-sp-d16` / `-mfloat-abi=hard` / 链接器 `--fpu` 全无效。
- **SDRAM 里的数组要写成 `.bss.*` 段名**，AC6 才当 ZI。否则显式命名段一律是 RW，
  启动时要把 512 KB 零从 FLASH 拷到 0xC0000000（FMC 还没起来）→ HardFault。
  `#pragma arm section zidata` 在 AC6 已废弃；`zero_init` 属性也不认。

### SDIO DMA（本轮核心）
现象：AC6 版本 `f_mount` 恒 rc=1；GCC 同码正常。降时钟到 8.4 MHz 两档都失败，
所以**与速率无关**。`err=0x20` = RX_OVERRUN。

根因：SDIO 接收 FIFO 只有 **128 B（32 words）**，21 MHz 下约 1.5 µs 就要取走一个字；
轮询循环里任何中断延迟都会溢出。AC6 的循环恰好踩线。

修法：`HAL_SD_ReadBlocks_DMA()` + DMA2 Stream3 Ch4，完成由
`HAL_SD_RxCpltCallback`/`ErrorCallback` 置 volatile 标志，`HAL_GetTick()`（TIM7）
做超时。写路径仍轮询。

> ⚠️ **必须 `Init.Mode = DMA_PFCTRL`（外设流控），不能用 `DMA_NORMAL`。**
> SDIO 只在 RX FIFO **半满（RXFIFOHF）** 时发 DMA 请求，`DMA_NORMAL` 下长度由 DMA
> 自己数，块尾凑不满半满阈值就永远等不到请求。实测判据：`ndtr=4`（只差 4 个字）、
> `lisr` 只有 HTIF3、SDIO 侧 `DCTRL.DTEN=0`（DATAEND 已到）。
> 正确配置按 ST 官方 SDIO 例程：`DMA_PFCTRL` + FIFO 模式 + `FIFO_THRESHOLD_FULL`
> + `MBURST_INC4`/`PBURST_INC4` + `PRIORITY_VERY_HIGH`。
> INC4 要求目标 **16 字节对齐**：`fs_diskio` 判断收紧到 16 B，`bsp_sdio` 内部再兜
> 一层按扇区 bounce。

中断：`SDIO_IRQn` 优先级 6、`DMA2_Stream3_IRQn` 优先级 5（DMA 必须高于 SDIO，
且都 >= `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`=5）。

时钟：用户要求**恢复原值 `SDIO_CLOCK_DIV = 2` → 21 MHz**（PCLK2 84/4；HAL 是从
PCLK2 派生，不是 PLLQ 48 MHz）。
