## 编译中修复的问题
1. `MCU_FLAGS` 必须是 **CMake list**（每项一个 flag），否则整串被当成单个 `-mcpu` 值报错。链接/ASM 阶段用 `list(JOIN ... " ")` 拼成字符串。
2. `main.c` 找不到 `app_main.h` → 把 `Application` 加入 `include_directories`。
3. `Bsp/drv_oled_fonts.c` 是 GBK 编码（含中文注释/字库索引标签），`-finput-charset=UTF-8` 报 "Illegal byte sequence"。已用 Python `gb18030→utf-8` 转码。其它被 `file` 误报 ISO-8859 的文件实际是纯 ASCII/UTF-8，无需处理。
4. `drv_oled_text.c` 中 `f_read(... &bytes_read)` 传 `uint32_t*` 但 FatFs 要 `UINT*`（32位下 `uint32_t=unsigned long` ≠ `UINT=unsigned int`）→ 把 `bytes_read` 改为 `UINT`。

## 关键设计点（已在先前置入，本次验证通过）
- 源码 UTF-8，编译期 `-finput-charset=UTF-8 -fexec-charset=GBK`：中文字面量存为 GBK，匹配 SD 卡 `GBKxx.FON` 索引。
- `-fdebug-prefix-map=${CMAKE_SOURCE_DIR}=.` → `.elf` 调试信息为相对路径 `./Core/Src/main.c`，满足"调试文件不用绝对地址"要求（已验证：elf 内无 `E:/...` 绝对路径）。
- 链接脚本 AXI-SRAM(0x24000000)；D-Cache 关闭以避免 SDMMC IDMA 一致性问题。

## 编译结果
- `build/lvgl_oled.elf/.hex/.bin` 均生成。
- Flash 59.5 KB / 2048 KB；RAM 23.2 KB / 512 KB。

# 追加：HSE 25MHz 无源晶振确认与时钟加固（同日）

用户明确硬件为 **25MHz 无源晶振**。核查后确认原配置已正确（`RCC_HSE_ON` 即无源晶振模式），但补齐了无源晶振特有的两个风险点。

## 现状核查（寄存器实测）
- `RCC_CR=0x0303c025`：HSEON=1、HSERDY=1、**HSEBYP=0（无源晶振模式，正确）**、CSSHSEON=0（未武装）。
- `RCC_PLLCKSELR=0x02020052`：PLLSRC=2(HSE)、DIVM1=5；`RCC_PLL1DIVR`：N=192、P=2 → 25/5×192/2 = 480MHz ✔。
- `RCC_CFGR=0x1b`：SW/SWS=3 = PLL1（注意 H7 编码 000=HSI,001=CSI,010=HSE,**011=PLL1**）。
- PH0/PH1 只使能了 GPIOH 时钟、无 `HAL_GPIO_Init`，保持模拟态 ✔。

## 加固改动
1. **`Core/Src/main.c`**
   - `SystemClock_Config()` 拆成两条路径：HSE 晶振失败 → 回退 HSI(64MHz)，`M=16→4MHz, N=240→960MHz, P=2` 仍得 480MHz；回退时把 HSE 一并 `RCC_HSE_OFF` 关掉（`OscillatorType` 需同时含 HSI|HSE 才会生效）。不再无提示死在 `Error_Handler()`。
   - HSE 就绪后 `HAL_RCC_EnableCSS()`。
   - 新增 `HAL_RCC_CSSCallback()`：**只置标志 + `SystemCoreClockUpdate()`**。NMI 里绝不能调 `HAL_RCC_OscConfig`/`HAL_Delay`，因 SysTick 无法抢占 NMI，`HAL_GetTick()` 永不前进会死锁。
   - 新增全局 `volatile ClockSource_t g_clock_source` / `volatile uint8_t g_hse_css_fault`。
2. **`Core/Inc/main.h`** — 新增 `ClockSource_t` 枚举（HSE_XTAL / HSI_FALLBACK / HSI_CSS_RESCUE）与两个 extern。注意 arm-none-eabi-gcc 默认 `-fshort-enums`，该枚举占 1 字节。
3. **`Core/Src/stm32h7xx_it.c`** — `NMI_Handler` 由死循环改为调用 `HAL_RCC_NMI_IRQHandler()`。
4. **`Application/app_main.c`** — banner 增打印时钟源（正常 `HSE : 25 MHz crystal OK (CSS armed)`，异常提示查 X1/负载电容）；`application_run()` 检测 `g_hse_css_fault` 并一次性告警。
5. **`CMakeLists.txt`** — 加 `-Wl,--no-warn-rwx-segments` 消除 RWX 段告警，构建现为 0 警告 0 错误。

## 实机验证结果
- 重新烧录 Verified OK；Flash 60.5KB(2.95%)、RAM 23.2KB(4.52%)。
- 串口 banner 新增行：`HSE    : 25 MHz crystal OK (CSS armed)`，其余全绿。
- `RCC_CR` 由 `0x0303c025` → **`0x030bc025`**，bit19 CSSHSEON=1，CSS 确认武装。
- `NMI_Handler` 反汇编确认 `bl HAL_RCC_NMI_IRQHandler`。
- 故障上报通路实测：运行中用 `openocd mwb 0x240000F4 0x01` 注入标志 → 串口立即打出 `[CLK] *** HSE CSS FAULT ***`。
- **晶振真实频率交叉验证**：openocd `sleep 20000` 作主机参考，前后读 `uwTick`(0x24001b50) 得 20002ms，误差 **0.010%**，反推 HSE=**25.0025MHz**，证实晶振确为 25MHz。
