## CTF 索引前部常驻 RAM（resident index）— 实现 + 端到端验证

### 需求（用户原话）
> 使用 ctf-ttf 字库时，初始化 sd 卡完成后，先把 ctf 中多级映射中第一部分关于 ttf 信息存储地址的
> 偏移映射搬运到 ram 里缓存，确定占用空间多少，如果满足第一层级就一直保存在 ram 中，增加效率

### 落点
`ctf_load_resident()`：在 `ctf_open()` 之后、`ctf_verify_ttf()` 之前调用（固件 `lvgl_font_engine_init()`
同顺序）。

### 常驻三段（不加载 entry 表、不加载 TTF）
- ① TTF 表目录 `N×12B`（鸿蒙实测 N=11 → 132B；上限 `CTF_TABLE_RESIDENT_MAX=64`）。
- ② L1 平面表（2KB，本就在 `ctf_open()` 搬）。
- ③ 页表 `page_index_count×40B`：**仅当整张能放进页池才全常驻**（all-or-nothing），否则退化走块缓存。
  页池 `CTF_PAGE_POOL_PAGES=288×40=11520B`（11.25KB），留余量。

### 安全
`page_pointers_ok()` 加载时一次性证伪所有非空平面 `page_offset` 落池内且 run 不越界，使 lookup 第二跳
`page_offset - page_index_offset` 减法恒不溢出，无需每查边界判断。

### 实测（板级 banner，COM19 ST-Link VCP）
```
[FONT] index in RAM 12420 B = tables 132 + L1 2048 + pages 10240
[FONT] pages resident: 10240 B of a 11520 B pool -> NOT_FOUND costs 0 SD reads
[FONT] entries stay on card: 697512 B
```
CTF probe 中 `U+1F600`/`U+0F8FF` 等缺字 SD 列 = 0 → 缺字判定零 SD 访问成立。

## TTF Glyph Cache（160 KB 独立栅格化字形缓存）— 实现 + 板级直读验证

### 需求（用户原话）
> TTF Glyph Cache 为 TTF 字库提供独立 Glyph Cache，Bitmap Cache 容量 160 KB；按 Unicode/Glyph ID 管理已栅格化字符，
> 再次使用优先从 Cache 获取，避免重复 TTF 解析/栅格化；空间不足 LRU 淘汰最久未用并回收；淘汰不得影响正在用/当前页固定字符；
> 建页用 TTF 字库则扫描文本去重 Unicode 建立预栅格化队列（GBK 跳过），预取尽量后台异步；切页优先预取当前页、旧页 LRU 自动淘汰；
> 实际绘制优先访问 Glyph Cache，Miss 再走 TTF 冷栅格化。

### 落点（全新增量，不碰 TTF/CTF/FatFs/stb）
- 新模块 `Bsp/font/glyph_cache.{c,h}`：160KB 池 `s_pool` 放 `.ram_d2`（0x30000000，288KB 空闲），
  变长字形用**边界标记空闲堆（free-list + 偏移排序 + 前后合并）**管理；entry 带 `lru` 戳 + `epoch` 页代次。
- `lvgl_font.c`：删除原 32KB `bmp_*` 定长回绕池，绘制改 `glyph_cache_lookup` 优先、`insert` 冷栅格化；
  新增 `utf8_next` / `scale_for_px` / `preload_enqueue` / `preload_timer_cb`（30ms 处理 4 字）/ `lvgl_font_px_of` /
  `lvgl_font_preload_text/label` / `lvgl_font_on_page_shown`（= bump_epoch）。
- `lv_font_provider.{c,h}`：引擎感知透传（仅 `FONT_ENGINE_CTF` 才预取/抬 epoch；GBK 因 `px_of==0` no-op）。
- `app_ui.c`：`mk_label` 末尾 `preload_label`；`take_switch` 清 pending 后 `on_page_shown` 抬 epoch。
- `CMakeLists.txt`：注册 `glyph_cache.c`。

### 关键设计决策
- **为何 RAM_D2 而非 RAM_D1**：160KB 进 AXI-SRAM 会使 RAM_D1 逼近 ~90% 危险区；挪 RAM_D2 后 RAM_D1 维持 ~61.7%、
  160KB 独占 RAM_D2 55.6%，皆安全。`s_pool` 仅 CPU 读，SPI6 DMA 不碰 → 无 cache 一致性问题。
- **epoch 钉扎替代引用计数**：查命中 `epoch=s_epoch; lru=++s_lru` → 当前页/正在用字形永不被淘汰；切页 `bump_epoch`
  使旧页落代次之后，压力下 LRU 自动回收、新页钉住。
- insert 分配失败才进 `while` 选 `epoch!=s_epoch` 且 `lru` 最小 victim 释放；无 victim 则返回 NULL（绘制跳过该字，不死锁）。

## 字体页首帧 200ms 卡顿消除（用户最高优先级指令）

### 指令
> 「第一次加载 ui_page_font.c 仍然比第二次多了 200ms 左右，表示优化未生效，优先解决这个问题」

### 根因（实机逐码点抓取 + DWT 计时）
- **首帧冷 miss 并非主因**：扩展 `app_main.c` `[PAGE]` 日志加 `ctf_page_sd / ttf_fills / ttf_read` 增量，
  首帧实测 `bmp_miss+0 | ctf_sd+0 ttf_fill+0 ttf_read+0 us` —— 位图池全命中、零 SD 读。200ms 差距不在字库。
- **真正根因 = LVGL 首绘一次性 CPU 开销**：screen 第一次实际绘制要做样式值计算 + label 排版 + draw-task 构建，
  首帧 refr 324ms / warm 130ms，差 ~194ms，纯 CPU、零 IO。
- **附带发现 Latin 预取漏洞**：`preload_enqueue()` 原 `if (cp<0x80) return;`（注释称 Latin 走 Montserrat）。
  但 `[MISS]` 门控日志抓到首帧拉丁字形 `U+00053('S')/U+00061('a')…` 冷 miss —— HarmonyOS CTF 索引**含拉丁**，
  LVGL 用 TTF 渲染而非 Montserrat，该 early-return 是错误的。

### 修复（仅 `Bsp/font/lvgl_font.c` + `Application/app_ui.c`）
1. `preload_enqueue()` 删 `cp<0x80` 跳过，Latin 一并预取入池。
2. `app_ui.c` 新增 `ui_warmup_pages()`：构建两页后**抑制显示 flush**（`dummy_flush_cb` 吞帧缓冲推送 + `lv_disp_flush_ready` 收尾）
   逐页 `lv_scr_load+lv_timer_handler` 各渲染一次，把"首绘一次性开销 + 字形冷栅格化"全挪到启动加载页背后（用户不可见）。
   首个真实翻页即 warm。成本体现：`[UI] built in ~880ms`（原 80ms）。

### 验证闭环
- 双构 **0 warning**；FLASH/RAM 占用不变（RAM_D2=200KB/288KB=69.44%，RAM_D1=61.73%）。
- Release 生产态烧录 Verified OK；决定性证据：
  ```
  [PAGE] switch -> 1, refr 129069 us, bmp_miss+0 ...   <- 首帧
  [PAGE] switch -> 1, refr 129109 us, bmp_miss+0 ...   <- 二次
  ```
  **首帧 129ms ≈ 二次 129ms，差距归零**。诊断用 `[MISS]` 门控日志已清理移除。
- README 新增 §8.17 归档本项。

### 复用要点
- 抓首次卡顿类问题：先看 `[PAGE]` 日志的 `bmp_miss / ctf_sd / ttf_fill / ttf_read` 增量区分「字库 miss」vs「纯 LVGL 渲染开销」，
  别一上来就怀疑字库缓存（本次误判过一次：曾以为 12 个 miss 来自 not-in-index，实际是 Latin 没预取、且 `[MISS]` 门控当时未 enable 导致漏抓）。
- 屏首绘慢→`ui_warmup_pages()` 抑制 flush 预渲染，是通用解法（任何多页 LVGL 工程都可用）。
- 诊断流程：先开串口后台抓（`serial_capture.py --port auto`），再 `openocd ... program ... reset exit`；门控日志须 `enable` 后才生效。

  断言首帧 `bmp_miss==0`、零 SD 读、`|首帧refr - warm均值|≤30ms`，退出码 0/1（CI 友好）；亦支持 `--in <文件>` 离线解析。
  仅统计 `[BOOT] done` 之后的 font 页样本，避免复位前旧固件日志误判。实机复跑 PASS（首帧 129085us / warm 129101us / delta -16us）。
