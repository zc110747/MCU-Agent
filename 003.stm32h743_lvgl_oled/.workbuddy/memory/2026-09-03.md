# 2026-09-03

## 字体系统重构：CTF 索引 + TTF 块缓存（替代直接 TTF 流式）

### 背景
原来让 stb_truetype 直接流式读 SD 卡上的 TTF，卡死在 `stbtt_GetGlyphKernAdvance()`
→ `stbtt__GetGlyphGPOSInfoAdvance()`：stb v1.26htcw 在 STBTT_STREAM 模式下**每个字节
一次 seek + 一次 1 字节读**，GPOS 表 ~32KB → 几万次 SD 事务。
另确认 **LVGL 8.3.11 的 label 绘制没有字距语义**，kerning 纯属白白付出代价
（kerning 调用点在 LVGL 自带 `lv_tiny_ttf.c:115`，不在我们的代码）。

### Phase 1 分析结论
- LVGL 8.3.11；stb_truetype v1.26htcw（带 STBTT_STREAM）；FatFs 盘符 `1:`；裸机无 RTOS。
- **D-Cache 关闭**（只开 ICache）；MPU region0 = AXI-SRAM 0x24000000 512KB，cacheable/write-back。
- 无外部 SDRAM，内部 RAM ~1MB → 整个 TTF / 整个 CTF 都不能进 RAM。

### Phase 2 完成：CTF v1 格式 + PC 工具
- 格式：Header(80B) + TTF表索引(12B×N) + L1(256×8B) + Page(M×40B，含256bit位图) + Entry(K×24B)。
  小端、定宽、显式偏移序列化，不依赖 struct 对齐。
- 寻址：plane=(u>>16) → page=(u>>8) → bitmap bit(u&0xFF) → popcount rank → entry。O(1)，无遍历无二分。
- **位图位为 0 = 缺字，立即 NOT_FOUND，零 SD/TTF 访问**（硬性要求）。
- Entry 不存 Unicode（位置隐含），24B/字；EMPTY（空格）与 NOT_FOUND 严格区分。
- 工具：`tools/ttf2ctf/`（ctf_format.py / ttf_parser.py / ttf2ctf.py），纯 Python 零依赖。
  支持 `--verify`（全量重推+缺字探测）/ `--info` / `--coverage` / `--dump`。

### 踩坑
- **页数组必须是稠密的**（page_no 直接索引，含空洞页），但 `total_pages` 一开始只统计了
  非空页 → `entry_offset` 基准偏了 4840 字节，所有 entry 读出乱码，lookup 全 NOT_FOUND。
  修法：`sum(max(p) + 1 for p in pages.values() if p)`。
- Python CLI 不认 MSYS 的 `/d/...` 路径，必须传 Windows 路径 `D:/...`。

### 字体选择结论（重要）
- `HarmonyOS_Sans_TC` 是**繁体子集**：GB2312 一级只覆盖 68%，UI 常用简体字 48 个缺 23 个。
- `HarmonyOS_Sans_SC` 覆盖 **100%**（29063 字 / CTF 693KB）。
- **默认字体用 SC**，TC 六字重保留作繁体显示。
- HarmonyOS 全部是 simple glyph（0 composite）；composite 路径用
  `C:/Windows/Fonts/arial.ttf`（2016 composite）单独验证通过。

### 生成结果（support_tools/sd_card/SYSTEM/，全部 --verify PASS）
| 字体 | CTF | 字符 | GB2312一级 |
|------|----:|-----:|-----------:|
| HarmonyOS_Sans_SC_Regular | 693 KB | 29063 | 100% |
| HarmonyOS_Sans_TC ×6 字重 | 354 KB ×6 | 14596 | 68.0% |

### 缺字与回退策略（用户明确要求）
CTF 查不到 → 立即 NOT_FOUND 不碰 TTF → LVGL 走 fallback → **内置 Montserrat（Flash 内部数据）**
→ 英文/数字照常显示。已启用 `LV_FONT_MONTSERRAT_12/16/24/32`（原本全为 0）。

- `tools/ttf2ctf/README.md`：完整格式说明 + 用法 + 生成结果 + 合成字形验证。
- 主 `README.md` 第 8 节：Phase 1 分析、Phase 2 成果、缺字回退策略、Phase 进度表。

## 缓存/MPU 架构原则纠正（用户 2026-09-03 反馈）

- **纠正**：本工程 D-Cache **实际是开的**（`main.c:47-48` `SCB_EnableICache/D Cache`；`MPU_Config()` Region0 把 AXI-SRAM 0x24000000 512KB 标 CACHEABLE）。之前 MEMORY.md 记的"D-Cache 保持关闭"是**过时错误结论**，已订正。
- **用户原话**：SDIO 没用 DMA，可以开 DCache；使用 DMA 情况也不应该关 DCache，而是应该使用 MPU；规划可以由我配合设计。
- **当前状态核对（正确且安全）**：I/D Cache 均开 + AXI-SRAM cacheable + SDIO 非 DMA（无共享 RAM 缓冲，CPU 走 SDIO 内部 FIFO）→ 无一致性问题。
- **未来 DMA 场景 MPU 草案（未落地，待用户定稿）**：Region0 AXI-SRAM 512KB 保持 Cacheable(WB)；为 DMA 缓冲单独划 non-cacheable 小 region（SDMMC IDMA 扇区缓冲 / SPI6(BDMA,D3 域) LCD 缓冲 → 放 SRAM4 0x38000000 64KB non-cacheable 等）。**待用户拍板**：①哪些外设上 DMA ②DMA 缓冲放哪块 RAM ③一致性策略 non-cacheable vs WT+手动 clean/invalidate。
- 链接脚本 `STM32H743ZITX_FLASH.ld`：主 RAM 刻意用 AXI-SRAM(0x24000000) 而非 DTCM（IDMA 够不到 DTCM）；DTCM 128K 仍导出供低延迟数据；RAM_D2 0x30000000 288K、RAM_D3 0x38000000 64K 可用。

## MPU 完整规划草案（SDMMC IDMA + SPI6 DMA 场景，待用户审）

**前提核实**：当前 `drv_sdio.c` 用 `HAL_SD_ReadBlocks`(轮询,CPU 搬 FIFO)，**非 IDMA**；`main.c:48` 已 `SCB_EnableDCache`，D-Cache 实际是开的。已订正 main.c/drv_sdio.c 两处"D-Cache 关/SD 用 DMA"的过时注释。

**H743 内存/总线要点**：IDMA 可达 AXI-SRAM(0x2400)/SRAM_D2(0x3000)/SRAM4(0x3800)，**不可达 DTCM(0x2000)**；SPI6 在 D3 域，DMA 用 BDMA(D3)→ 像素缓冲放 SRAM4(0x38000000) 同域最顺。

**MPU Region 表（草案）**
| # | Base | Size | 属性 | 用途 | Bank |
|---|------|------|------|------|------|
| 0 | 0x24000000 | 512KB | Normal Cacheable(WT) | 通用 RAM/栈/字体池 | AXI-SRAM(D1) 现状保留 |
| 1 | 0x30000000 | 16KB | Normal **Non-cacheable** | SDMMC IDMA 扇区缓冲 | SRAM_D2(D2) |
| 2 | 0x38000000 | 16KB | Normal **Non-cacheable** | SPI6(BDMA) LCD 发送缓冲 | SRAM4(D3) |
| 3 | (可选)余下 SRAM_D2 | 余下 | Cacheable | D2 其他数据 | SRAM_D2 |

**关键设计**：Region1/2 non-cacheable → CPU 与 DMA 看同一份内存，**无需手动 clean/invalidate**，即"用 MPU 而非关 D-Cache"。Region1/2 与 Region0 不同 bank 不重叠，优先级无关。

**链接脚本**：新增 `.sd_idma_buf`(>RAM_D2) / `.spi6_dma_buf`(>RAM_D3) 两段 NOLOAD；C 端 `__attribute__((section(".sd_idma_buf"),aligned(16)))` 定义缓冲；`MPU_Config()` 扩展 Region1/2(MAIR non-cacheable)；SD 改 `HAL_SD_ReadBlocks_DMA`+完成回调，SPI6 改 `HAL_SPI_Transmit_DMA`。

**待用户拍板**：①缓冲大小（SD 一次最大读几块？LCD 帧 115KB 放不下 SRAM4，需行/块流式缓冲）；②SRAM 选址（SD→D2 / SPI6→D4 分法是否认可）；③是否现在落地还是仅存档。
