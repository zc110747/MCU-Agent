# 2026-09-03

## 字体系统重构：CTF 索引 + TTF 块缓存（替代直接 TTF 流式）

### 背景
原来让 stb_truetype 直接流式读 SD 卡上的 TTF，卡死在 `stbtt_GetGlyphKernAdvance()`
→ `stbtt__GetGlyphGPOSInfoAdvance()`：stb v1.26htcw 在 STBTT_STREAM 模式下**每个字节
一次 seek + 一次 1 字节读**，GPOS 表 ~32KB → 几万次 SD 事务。
另确认 **LVGL 8.3.11 的 label 绘制没有字距语义**，kerning 纯属白白付出代价
（kerning 调用点在 LVGL 自带 `lv_tiny_ttf.c:115`，不在我们的代码）。

### Phase 1 分析结论
- LVGL 8.3.11；stb_truetype v1.26htcw（带 STBTT_STREAM）；FatFs 盘符 `1:`；裸机无 RTOS。
- **D-Cache 关闭**（只开 ICache）；MPU region0 = AXI-SRAM 0x24000000 512KB，cacheable/write-back。
- 无外部 SDRAM，内部 RAM ~1MB → 整个 TTF / 整个 CTF 都不能进 RAM。

### Phase 2 完成：CTF v1 格式 + PC 工具
- 格式：Header(80B) + TTF表索引(12B×N) + L1(256×8B) + Page(M×40B，含256bit位图) + Entry(K×24B)。
  小端、定宽、显式偏移序列化，不依赖 struct 对齐。
- 寻址：plane=(u>>16) → page=(u>>8) → bitmap bit(u&0xFF) → popcount rank → entry。O(1)，无遍历无二分。
- **位图位为 0 = 缺字，立即 NOT_FOUND，零 SD/TTF 访问**（硬性要求）。
- Entry 不存 Unicode（位置隐含），24B/字；EMPTY（空格）与 NOT_FOUND 严格区分。
- 工具：`tools/ttf2ctf/`（ctf_format.py / ttf_parser.py / ttf2ctf.py），纯 Python 零依赖。
  支持 `--verify`（全量重推+缺字探测）/ `--info` / `--coverage` / `--dump`。

### 踩坑
- **页数组必须是稠密的**（page_no 直接索引，含空洞页），但 `total_pages` 一开始只统计了
  非空页 → `entry_offset` 基准偏了 4840 字节，所有 entry 读出乱码，lookup 全 NOT_FOUND。
  修法：`sum(max(p) + 1 for p in pages.values() if p)`。
- Python CLI 不认 MSYS 的 `/d/...` 路径，必须传 Windows 路径 `D:/...`。

### 字体选择结论（重要）
- `HarmonyOS_Sans_TC` 是**繁体子集**：GB2312 一级只覆盖 68%，UI 常用简体字 48 个缺 23 个。
- `HarmonyOS_Sans_SC` 覆盖 **100%**（29063 字 / CTF 693KB）。
- **默认字体用 SC**，TC 六字重保留作繁体显示。
- HarmonyOS 全部是 simple glyph（0 composite）；composite 路径用
  `C:/Windows/Fonts/arial.ttf`（2016 composite）单独验证通过。

### 缺字与回退策略（用户明确要求）
CTF 查不到 → 立即 NOT_FOUND 不碰 TTF → LVGL 走 fallback → **内置 Montserrat（Flash 内部数据）**
→ 英文/数字照常显示。已启用 `LV_FONT_MONTSERRAT_12/16/24/32`（原本全为 0）。

## Phase 3~8 全部完成（本轮收尾）

### 新增源码（Bsp/font/）
- `ctf_reader.c/.h`：三级直接寻址；`CTF_NOT_FOUND` 正常返回值不刷屏；两段式边界检查；
  `ctf_entry_is_empty()` 区分空格；`ctf_verify_ttf()` 绑定 size(+可选CRC32)；L1 shadow 常驻 2KB。
- `blkcache.c/.h`：通用 LRU 块缓存（≤8 块，跨块合并、尾块用 `*br` 有效长度、age 时间戳）。
- `ttf_reader.c/.h`：全工程唯一 SD 随机读收口点（`ttf_fill()` 一处 f_lseek+f_read）。
- `stb_adapter.c/.h`：stb 源码零修改，`STBTT_STREAM_*` 宏接 ttf_reader → seek 变一次 store、
  read 走块缓存；读失败清零缓冲；bump arena 36KB（s_live 计数全释放即重置）；
  box 一致性自检（CTF 度量 vs stbtt_GetGlyphBitmapBox，主机+实机均 0 mismatch）。
- `lvgl_font.c/.h`：lv_font_t 后端。`get_glyph_dsc` 纯索引零 TTF 访问；位图池 32KB/176slot；
  fallback → Montserrat 12/16/24/32（编译期断言）；统计导出 + 板级自检探针 `lvgl_font_selftest()`。

### 关键修改
- `lv_conf.h`：`LV_USE_FONT_PLACEHOLDER 0`（缺字不画框，文本合拢）。
- `lv_font_cfg.h`：`LV_FONT_ENGINE_CTF 2` 默认（2=CTF+TTF / 1=TTF直读 / 0=GBK点阵）。
- `lv_font_provider.c`：`lv_font_provider_locate()` 先试配置名再扫目录第一个 .ctf。
- `CMakeLists.txt`：stb 头路径 tiny_ttf + 两个新源文件。
- `ttf2ctf.py`：`--info/--dump/--coverage` 不再强制重建索引。

### 主机端验收（tools/host_test/，PC 上编译固件真实源码跑真实字体）
- `host_shim/ff.h`：stdio 版 FatFs 替身（EOF 短读 = FR_OK + *br<btr，与真实 FatFs 一致）。
- `ctf_host_test.c`：5 组测试，含全 Unicode 0..0xFFFF 遍历。**7 字体全绿**（SC 81 / TC 35×6, 0 failed）。
- **块缓存量化证据：整轮测试（含 65536 码位遍历）只发 20 次 f_read()**；无缓存是几十万次。
- 主机测试抓到 4 个真 bug：entry_at 未初始化（误删赋值）、shim EOF 短读语义错、
  尾块断言期望值错、ttf2ctf --info 重建索引。
- 一键脚本 `tools/host_test/run_host_test.bat`（gcc 在 PATH，自动扫 SD 镜像所有 ctf+ttf 对）。

### 板级实测（Release 烧录，COM19 @115200）
